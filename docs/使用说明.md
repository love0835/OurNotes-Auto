# 使用说明

[README](../README.md) 之外的详细说明：各任务的细节、游戏内设置、自动修正、拟人化、出意外时的处理、运行时文件和工作原理。命令行用法见[命令行](命令行.md)。

## 环境要求

- Windows，MuMu 模拟器 12（本项目在 MuMu 6.6.x、Android 15 实例上测试）
- 模拟器分辨率 **1280×720**（其他 16:9 分辨率会按比例换算，但未充分测试；不是 16:9 的启动时会报错），帧率不低于 60（同步参数按 60 帧截图调整）
- 游戏：国际服（包名 `com.bilibili.sirius.official`；Google Play 版是 `com.bilibili.sirius`，会自动识别），游戏语言为简体中文、繁體中文、English 或 한국어；或日服（包名 `com.bushiroad.sirius`）。导航靠 OCR 识别界面上的文字，其他服认不出按钮。한국어要把「游戏语言」选成 한국어：第一次运行时会自动下载韩文文字识别模型（约 10 MB），之后每次多加载它（两个模型一起识别，每次识别慢一些）；不选 한국어 不会下载也不会加载
- 日服：把「游戏语言」选成「日本語（日服）」，启动游戏等任务就操作日服客户端（不用另外下载识别模型）。日服客户端要从 Google Play 安装，直接装 APK 打不开。切换账号只能用于国际服。T.G.W CARD 和商店要先在游戏里自己做一次年龄确认，没做时领取日常会跳过 T.G.W CARD。日服只验证过自由演出、AP补完和领取日常，挑战演出还没在日服试过
- 游戏内设置见[游戏内设置](#游戏内设置)
- 能访问谱面站 `assets.bdon.moe` 与曲名接口 `haneoka.org`（检查更新、自动更新另外访问 `github.com`，可以关掉）。浏览器打得开、这里一直下载失败（日志里「下载失败…远程主机强迫关闭了一个现有的连接」）时，在全局选项「网络代理」里填代理软件的 HTTP 端口（如 `127.0.0.1:7890`），命令行设环境变量 `HTTPS_PROXY`
- 发布包：两种界面都需要 [VC++ 2015–2022 运行库](https://aka.ms/vs/17/release/vc_redist.x64.exe)（MaaFramework 依赖）；MFAA 另外需要 .NET 10 桌面运行时（包里的 `DependencySetup_依赖库安装_win.bat` 可一键安装它和 VC++ 运行库），MXU 需要 WebView2（Windows 10/11 一般自带）。包里自带 Python 运行时、MaaFramework 与 OCR 模型，谱面在运行时从谱面站下载。各组件的许可证见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)
- 从源码运行：Python ≥ 3.11，见[命令行](命令行.md)

## 连接模拟器

连接设置里选「MuMu 模拟器」，再选要用的模拟器实例。MuMu 12 第 n 个实例的 adb 地址是 `127.0.0.1:16384+32n`，例如第 0 个是 16384，第 1 个是 16416。截图和触控走 MuMu 的接口，安装目录由 adb 路径推出，所以目前只支持 MuMu 12。

## 任务

游戏停在主界面或自由演出选曲页即可；游戏没开也行，除了「跟打」「打开统计窗口」「推送测试」，其余任务都会先启动它（已经开着就直接用），再等过标题画面、登录奖励和公告进入游戏。

| 任务 | 作用 |
|---|---|
| 启动游戏 | 游戏没在运行时启动它，点掉标题画面、登录奖励和公告，进入主界面。其他任务（除「跟打」「打开统计窗口」「推送测试」）都会先做这一步，不用单独勾选 |
| 切换账号 | 只限国际服。退出当前的 B 站账号，从游戏的登录记录里选填写的账号登录（不用输密码），然后进入主界面；已经在游戏里时先重启游戏回到标题画面。账号名填登录记录里显示的名字，写一部分也行，但要只对得上一个账号。只能切到登录记录里有的账号，新账号请先在游戏里手动登录一次。多个账号轮流打：任务列表里排成「切换账号（A）→ 其他任务 → 切换账号（B）→ 其他任务」。用户中心的「注销」、登录记录每行右边的 ⓧ 都不会点。演奏记录、统计与成就目前不分账号 |
| 重复刷歌 | 在自由演出里连续演奏，可选选曲方式（当前曲 / 随机 / 优先未 AP / 指定歌单）、难度、局数、每局消耗的 LB。难度选「优先高难度」时，「优先未 AP」从 EXPERT 到 EASY 依次补，都补完了按 EXPERT 随机；其他选曲方式按 EXPERT 打 |
| 清体力 | 连续演奏到 LIVE BOOST 用完（每局前看持有数，为 0 就结束），不用星钻。升级会回满 LB，所以局数可能比预计的多 |
| 挂机 | 和清体力一样打到 LB 用完，然后停在乐队确认页，按右上角的恢复倒计时等 LB 恢复到每局消耗数，再接着打（LB 每 30 分钟恢复 1 个，消耗 3 时约 90 分钟一局）。每局消耗选 0 时不等 LB：每局前看持有数，有 LB 就消耗 1 个，用完了改为消耗 0 接着打，恢复出来再消耗，一直打歌。一直运行到手动停止或打够局数；等待时遇到日期变更会重新登录，遇到服务器维护每 10 分钟看一次，开服后接着挂机。选项「定时收获」（默认开，间隔 4 小时）：开始时先领一次录音室练习，之后每隔设置的小时数（1~12）在两局之间或等 LB 时回主界面再领一次，领完回来接着挂机（录音室练习最多累计 12 小时，超过后效率降到 30%）；没领成的过 30 分钟再领。选项「每天领取日常」（默认开，22:30）：每天到设置的时间（电脑的本地时间）同样回主界面领一次任务、任务通行证、限定任务、新手任务、T.G.W CARD、免费招募和礼物盒，没领全的过 10 分钟再领一遍（一天最多 3 遍）。任务列表里的「领取日常」只在挂机前跑一次，挂机跨天后靠这个领；游戏每天 23:00 日期变更，领取时间要早于 23:00 才领得到当天的。不用星钻。它不会自己结束，请放在任务列表的最后 |
| AP补完 | 把所选难度（EXPERT / HARD / NORMAL / EASY）里还没 ALL PERFECT 的歌打到 AP。会临时把选曲页切到「全部」分类、筛选「未ALL PERFECT」，正常结束后改回原样。同一首打了「每首最多尝试」次还没 AP 就不再打；其中每次都没打完（同步失败、生命值归零）的谱面会记下来，3 天内 AP补完和「优先没 AP 的歌」都不再打它（多半是游戏更新后谱面对不上，过几天再试） |
| 挑战演出 | 只在部分活动期间开放（没开放时报错结束）。从演出首页进「挑战演出」连续演奏，每局消耗挑战pt（CP）而不是 LB，打到 CP 不够一局为止。持有数不够所选的消耗时游戏不让点 OK（提示「挑战pt不足。」），这时点「取消」后停下，不会一直点 OK 到超时。选项「每局消耗挑战pt」默认 200（×1，最省、能多打几轮），也可选 400 / 800 / 1600（奖励 ×2 / ×4 / ×8）或不改游戏里的设置；第一局前在「CP 设置」里选好并核对单选按钮后才点 OK。选曲方式「轮流打每首歌」（默认）每局换到列表里的下一首，到底了回到第一首；「优先打没 AP 的歌」每局开始前逐首看所选难度有没有 ALL PERFECT，先打没 AP 的（同一首最多打 3 次），都 AP 了再轮流打（难度选「优先高难度」时按 EXPERT → HARD → NORMAL → EASY 依次补）；也可以一直打当前选中的歌。乐队确认页的「跳过」不会点 |
| 跟打 | 只帮你打歌，其他都自己点：自己选歌、点 LIVE START 开始演出，进入演奏画面（看得到右上角的暂停按钮）时开始同步、自动打歌。曲目在乐队确认页认，所以要经过乐队确认页（认不出、谱面站没有这首时这一首不打，日志里有说明）；难度按画面上的读，读不出时按等级定。自由演出和挑战演出都行。LIVE CLEAR、结算页翻页、弹窗都等你自己点，只在结算页上点一下 ⇄ 读 FAST/SLOW，和其他任务一样记录成绩、修正 offset（读完判定数之前就点了下一步，这一局不记录；读完判定数、还没读 FAST/SLOW 时点了，只记判定数）。演奏中暂停后点重试并确认，会从头接着打这一首；点继续接不上，这一局不打了。同步没跟上时这一局也不打，可以自己暂停重试。不启动、不重启游戏，一直运行到手动停止 |
| 领取日常 | 依次领取录音室练习（收获）、任务、通行证任务与 PASS 普通档（同时有几个通行证时逐个领）、限定任务、新手任务、T.G.W CARD、免费招募、礼物盒的奖励，每项可单独关掉。只点亮着的「一键领取」和奖励弹窗的 OK；T.G.W CARD 领每日积分、每日奖励和商店专享商品目录里价格写着「免费」的商品，要星钻的不点；免费招募（默认开）只在主界面「招募」上有「免费招募」角标时做，按钮写着「免费」「1次」、确认框写着「将消耗0个星钻」才点，抽卡演出点 SKIP，结算后只点「招募TOP」（不点「再次招募」、付费招募和广告），结果截图存在 `data/recruit/`，MXU 的日志里直接显示，前后核对星钻数没变；不认得的弹窗不点，报错停下。打完歌后每日任务才满，所以排在演奏任务后面。可选「看故事（跳过）」（默认关）：把没看过的乐队故事、视角故事、羁绊故事逐话跳过，解锁乐曲、领看完的奖励，每话第一次看要下载数据（无语音，乐队故事约 30MB）。可选「活动故事（跳过）」（默认关）：限时活动期间从演出首页 →「活动」进活动页（同时有好几个活动、先弹出「活动选择」时点举办中的那个），把「活动故事」里没看过的活动故事、视角故事逐话跳过；没有限时活动时跳过这项 |
| 打开统计窗口 | 打开「统计与成就」窗口（见下面的「统计与成就」；换包前在窗口里导出记录，见「备份与恢复」），并在日志里列出演奏记录（各难度 AP 过的谱面、打过还没 AP 的谱面、最近 10 局）。不操作模拟器 |
| 推送测试 | 按全局选项「推送到手机」发一条测试消息（见下面的「推送到手机」）。不操作模拟器 |

### LB 不足时用道具补充

重复刷歌、清体力、挂机、AP补完都有选项「LB 不足时用道具补充」（默认关）：每局开始前 LB 持有少于每局消耗数时，从「消耗LB」→「恢复」进去，只在「道具」页用 LIVE BOOST饮料补够这一局（先用小型 +1，不够再用 +10），核对选中的数量、恢复预览和确认弹窗上的数字都对得上才点 OK；不在「道具」页或有任何对不上就点取消、本次不再补充。绝不用星钻、不看广告。

子选项「最多补充」是本次运行最多补充的 LB 数，0 为直到饮料用完。饮料用完后按原来的方式继续（清体力就此结束，挂机开始等恢复）。需要把每局消耗 LB 设为 1~5 或「自动」。

### 每局消耗 LB：4、5 与「自动」

「每局消耗 LB」可选 0~5（重复刷歌、AP补完还可选不改游戏里的设置）。4、5 要 T.G.W CARD 10 级、14 级解锁；没解锁时按「消耗LB」弹窗里能选的最大值，日志里会提示。

选「自动（按持有数）」时每局开始前打开「消耗LB」弹窗，按当时的持有数选：

- 一般选能选的最大消耗（没解锁 4、5 时为 3）；持有数不够就选持有数，把剩下的全部消耗掉。
- 「全部消耗」（一局最多消耗 10 个，持有 4 个以上才能用；每天能用几次看月卡，比如最高档月卡每天 5 次）在下面两种情况下用：持有 10 个以上；或者用它比一局局消耗能少打 2 局以上（比如持有 7 个、最大消耗 3 时，一局局消耗要打 3 局，全部消耗只要 1 局）。
- 「全部消耗」用到今天的次数用完为止（在游戏里手动用掉的也算）：弹窗上显示「今日次数已用完」、或者今天用过之后再勾不上时，记在 `data/state.json`（用「切换账号」轮流打多个账号时按账号分开记），当天（游戏日期，每天 23:00 变更）不再看。
- 清体力选自动时打到 LB 用完就结束；挂机选自动时 LB 用完后每恢复 1 个就消耗掉，不等攒够。挂机选 0 时仍是原来的「有就消耗 1 个，没有就消耗 0」。

### 使用跳过

清体力、挂机有选项「使用跳过」（默认关）：每局前先点乐队确认页的「跳过」，在确认弹窗里按「每局消耗 LB」选好消耗（自动时同样会用「全部消耗」）后跳过当前选中的歌，每天的跳过次数用完了再演奏。跳过不算在局数里，结束时的日志里列出跳过了几次。

- 只在这一局会消耗 LB 时跳过（每局消耗 1~5 或自动；挂机选 0 时有 LB 才跳过，消耗 1 个）。LB 用完了不点跳过（确认弹窗里看到持有 0 时点「关闭」），按原来的方式继续。
- 挑战演出的「跳过」不会点。

### 其他选项

- 需要调整默认值以外的参数（如时间偏移）时，把 [config.example.yaml](../config.example.yaml) 复制为解压目录里的 `config.yaml` 再修改。界面里的选项优先于它。
- 界面日志默认只显示进度和结果。打开全局选项「调试日志」后，同步、谱面、触控等细节也会显示；完整日志总是写在 `data/ournotes.log`。
- 全局选项「检查更新」「自动更新」默认开启：任务开始时查 GitHub 上有没有新发布的版本（MFAA 打开界面、连上模拟器时也按上次运行任务时的选项查一次），有就在后台下载，进度和结果在任务结束时的日志里提示。
  - 只改了演奏部分时，没有任务运行就直接换上，下个任务用新版本；不限次数的挂机会在两首歌之间暂停一下，换好后自动继续。
  - 改了界面要读的内容（任务、选项、界面文字）时，要重启界面：没有任务运行、界面闲置 2 分钟后自动关掉界面，换好后重新打开（不会自动开始任务）。界面设成打开就自动开始任务时（MXU 的「手动启动时也自动执行」，MFAA 带「启动脚本」的启动方式）不替你重启，关掉界面后自动换上。
  - 界面程序、Python、依赖或文字识别模型变了时，下载整个压缩包替换，时机同上。`config/`、`data/`、`cache/`、`debug/` 和界面自己的设置不动。
  - 换之前的文件备份在 `cache/update/backup/`；新版本启动不了会自动换回原来的版本，在日志里提示，这个版本不再自动更新。如果还原也失败，会保留备份并停止任务和自动更新；请按日志手动恢复，或把发布包解压到新目录后再运行。
  - 关掉「自动更新」只提示有新版本，要手动下载新的压缩包。没有「自动更新」选项的旧版本要手动下载一次。

### 统计与成就

累计运行时长、演奏数据（每天的局数、各难度、各谱面的战绩）和成就（有几个是隐藏的），每局后更新；有这个功能之前的运行时长按演奏记录估算。只统计本工具打的局，页面目前只有中文。在这几个地方看：

- 「统计与成就」窗口：运行任务「打开统计窗口」，或者双击包目录里的「统计与成就」快捷方式（从界面运行过任意一个任务后自动建好）。打完一局自动刷新，解锁成就时弹出提示；正在运行的任务在概览最上面显示正在做什么（演奏哪首歌、下一个 LB 还要多久恢复等），几秒更新一次；已经开着时切到前面。用 Edge 的应用模式打开（没有 Edge 时用 Chrome，都没有时用默认浏览器）。
- MXU：「设置」页最上面的「统计与成就」卡片，重新打开设置可以刷新；卡片底部的「在浏览器里打开」用默认浏览器打开和窗口里一样的页面（要开着 MXU 自带的 Web 服务，默认开着）。
- MFAA：任务「打开统计窗口」的说明，点一下别的任务再点回来可以刷新；说明最后有打开窗口的链接。

任务结束时日志里写一行本次运行的时长和累计数据，解锁成就时写一行「★ 解锁成就」。

### 备份与恢复

演奏记录、运行记录、成就和学到的时间偏移都在包目录的 `data` 里，删掉包、换成新下载的完整包时会跟着没掉。换包前在「统计与成就」窗口右上角点「备份与恢复」导出一份（MXU 设置页卡片的「在浏览器里打开」打开的页面不能导出、导入，要在窗口里做）：

- 「导出备份」：选好存到哪里，存成一个 `OurNotes-Auto-backup-<时间>.zip`。放在包目录外面（如「文档」），删掉旧的包也还在。
- 「导入」：在新的包里打开「统计与成就」窗口，点「选择备份文件」选导出的 zip。没导出过、旧的包还在时，展开「没导出过？从旧的包目录导入」，填旧的包目录（或它的 `data` 文件夹）点「读取」。先显示会导入多少，点「确认导入」才导入，导入完页面自动刷新。
  - 是合并，不是覆盖：这个包里已有的记录一行不动，只补上没有的，同一局、同一次运行不会重复；成就按早的解锁时间。同一份备份再导入一次不会有改动。
  - 学到的时间偏移只在这个包还没学过时导入。全局偏移跟电脑、模拟器有关，只在导出的那台电脑上导入；按谱面的偏移在别的电脑上也导入。
  - 要改的文件先复制到 `data/import_backup/<时间>`（留最近 5 次），导入的结果不对时可以从那里拿回来。
  - 有打歌任务在运行时不能导入（它们也在写演奏记录），先停止。导入时开始的任务会等导入完再开始。
  - 新版本导出的备份，可能要先把这个包更新到那个版本才能导入（会提示）。
- 招募截图（`data/recruit`）和 `config.yaml` 不在备份里，要的话自己复制。新的包还没打过歌时，直接把旧的包的 `data` 文件夹复制过去也一样。

### 推送到手机

全局选项「推送到手机」选好推送方式、填好「推送地址」后，这几种情况会发一条消息到手机：

- 打歌任务（重复刷歌、清体力、挂机、AP补完、挑战演出）完成：打了几局、FC / AP / 失败各几局、用时多久。领取日常完成时也推送一条。
- 任务出错结束：出了什么错（日志里最后一条错误）和用时。跟打、启动游戏、切换账号只在出错时推送（跟打一直运行到手动停止，没有「完成」）；打开统计窗口不推送。
- 挂机遇到服务器维护：开始等的时候推一条，开服、接着挂机时再推一条。

手动停止的任务不推送。「推送哪些消息」选「只推送出错和服务器维护」时不推送完成。

| 推送方式 | 设置 |
|---|---|
| ntfy | 免费，不用注册。手机装 ntfy 应用（安卓、iOS），订阅一个别人猜不到的主题名（字母、数字、- 和 _），把主题名填进「推送地址」。自建的 ntfy 服务填完整网址，如 `https://ntfy.example.com/主题名` |
| Server酱（微信） | 推到微信。在 [sct.ftqq.com](https://sct.ftqq.com/) 用微信扫码登录，复制 SendKey 填进「推送地址」（Server酱³ 的 SendKey 也可以）。免费版每天能推的条数有限，可以只推送出错和服务器维护 |
| Bark（iPhone） | 推到 iPhone。在 App Store 装 Bark，打开后复制它给的网址（如 `https://api.day.app/你的key/`，后面带着示例的推送内容也可以）填进「推送地址」，也可以只填 key。自建的 Bark 服务器填 `https://服务器地址/你的key`。出错的消息是时效性通知，开着专注模式也会提醒 |
| webhook | 把消息以 JSON POST 到「推送地址」填的网址：`event`（`done` / `error` / `maintenance` / `test`）、`title`、`text`、`time`（Unix 时间戳），用来接自己的机器人或别的推送服务 |

- 设好后运行任务「推送测试」（不操作模拟器），看看手机收不收得到；没收到时日志里写着原因。
- 「推送地址」等于密码：别人拿到就能给你发消息，ntfy 的主题还能被别人订阅、看到你的消息。别发给别人，日志里也不会记。
- 推送失败（网络不通、地址填错、超出 Server酱的每日条数）只在日志里记一条警告，任务照常运行。
- 命令行运行时在 `config.yaml` 的 `notify` 里设置（见 [config.example.yaml](../config.example.yaml)），用 `ournotes-auto notify-test` 测试。

## 游戏内设置

| 设置 | 建议 | 说明 |
|---|---|---|
| 节奏图示速度 | **5.00**（必须） | 同步参数 `play.sync.tau_s = 0.835` 是在 5.00 下测的。每局开始前会从演出前选项设置弹窗读出流速核对，不一致只在日志里警告、不会停下：其他流速仍能同步，但按键时机整体偏移。改回 5.00，或执行 `calibrate motion` 重新测量（另见[拟人化](#拟人化可选默认关闭)一节的流速要求） |
| MV / 背景 | 关闭，或换成较暗、不动的背景（必须） | 开局要等画面静止后再跟踪第一个音符。背景一直在动时最多等 4 秒就开始跟踪，亮的背景还会混进来，导致同步失败或不准 |
| 小节线显示（详情 → 节奏图示设置） | 开关都可以 | 开局跟踪第一个音符时，会认出横贯轨道的小节线并跳过。0.1.3 及更早的版本会把比第一个音符先落下的小节线当成第一个音符，整局提前、很快生命值归零，用这些版本时请关掉 |
| 特效、演出等级 | 不强制，电脑配置弱时建议调低 | 只在开局几秒看画面（这时还没有击打特效），彩色特效会被过滤；之后按谱面演奏，只看右上角的暂停按钮。但目前只在调低的设置下测过，高特效下可能有亮白色的开场特效混进跟踪区，或全屏演出连续遮住暂停按钮超过 2 秒被当成离开演奏画面而停止触控。调低还能让模拟器帧率更稳 |
| 乐队确认页「消耗LB」 | 用配置项 `game.lb_cost`（0~5）或 `game.lb_auto` 自动设置 | 第一局前自动打开弹窗选好并核对，游戏会记住。0 不消耗 LB（LIVE START 上显示「n ▸ n」）。LB 不够时游戏会消耗剩余全部；弹出「恢复LIVE BOOST」（道具/星钻/广告）时只点取消，该局改为 0（开了 `game.lb_refill` 时先用道具里的 LIVE BOOST饮料补充，见[上文](#lb-不足时用道具补充)）。留空（null）则不改游戏里的设置 |

换电脑、换模拟器实例或重装后，先用低难度打一两首，看日志里有没有同步失败或流速警告。不同电脑的截图、触控延迟不一样，不用手动调：自动修正会逐局调整时间偏移，每局最多 1ms（见[时间偏移与自动修正](#时间偏移与自动修正)）。

## 时间偏移与自动修正

`play.offset_ms` 是全局时间偏移，正值表示整体更晚按下，用来补偿截图、输入、渲染带来的延迟。MuMu 上实测约 -16ms 时判定居中。

每局结束后，程序读取结算页的 FAST/SLOW。FAST 多就往后推，SLOW 多就往前拉，把学到的偏移存进 `data/state.json`（与配置里的 `offset_ms` 叠加）。以下情况只记录、不修正：执行不稳定（迟到的批次多），或者 GOOD/BAD/MISS 过多（多半同步到了错误的音符）。

### 按谱面修正

有的谱面一直偏 FAST 或偏 SLOW（实测 56 张打过 4 局以上的谱面里 22 张平均偏差很大），全局偏移被它们来回拉。开启 `play.auto_tune.per_chart`（默认开）后，某张谱面最近 `chart_plays` 局（默认 3）的偏差方向都和全局近况相反、且平均绝对值不小于 `chart_threshold`（默认 0.4）时，这段偏差算这张谱面自己的：只调它自己的偏移（每张谱面不超过 ±`chart_max_ms`，默认 ±10ms），这一局不动全局偏移。谱面偏移按流速分开记，换了流速要从头学。

用 `ournotes-auto records` 看时，学过的谱面偏移会一起列出来（偏得多的在前）；`ournotes-auto records --clear-chart-offsets` 可清除所有谱面偏移（全局学习值不变），谱面大改（比如游戏更新换了谱面）后清一次再重新学。

## 拟人化（可选，默认关闭）

让结果不那么整齐。界面里在全局选项中，命令行用 `--set` 修改：

| 配置项 | 界面选项 | 作用 |
|---|---|---|
| `play.touch.great_ratio` | 随机 GREAT（1% / 3% / 5%） | 按判定总数的这个比例，挑前后没有别的音符挨着的普通点击，提前或延后 64~69ms 打成 GREAT（单局同步误差偏大时其中一部分会变成 PERFECT 或 GOOD，GOOD 不断连击）。选曲方式为 `ap` / `ap_first` 时不生效。开启后自动修正偏移时不计 GREAT 的 FAST/SLOW |
| `play.touch.jitter_ms` | 时机偏移（±8 / ±16ms） | 按下时刻随时间缓慢漂移（最多 ± 设定值），另加每个手势最多 ±3ms 的独立抖动。上限 20ms |
| `play.touch.position_jitter` | 触控位置随机 | 触控点在音符宽度内随机横移，并上下小幅挪动。不会挪进旁边点击类音符的判定区（否则按下可能被它认领），按住的长条也不会挪进同时按住的另一个长条的判定区。取值 0~1 为幅度，界面开关打开时为 1 |

例：`ournotes-auto --set play.touch.great_ratio=0.03 --set play.touch.jitter_ms=8 --set play.touch.position_jitter=1 run`

开了「随机 GREAT」时请把游戏内节奏图示速度保持在校准过的那个值（默认 5.00）。GREAT 的判定区间是 ±83ms，
故意打的 GREAT 落在偏 64~69ms 处，留给整体偏移的余量只有十几毫秒：流速不是校准时用的值，
偏移就可能超出去，延后打的 GREAT 变成 GOOD（连击还在，但结果不对）。
流速越快，首音符的跟踪时间越短（5.00 约 1.8 秒、10.00 约 0.45 秒），单局内的同步误差也越难被平均掉，
所以这个余量在 10.00 下最紧。

## 意外情况

- 演奏中连续 `play.guard_lost_s` 秒（默认 2）看不到右上角的暂停按钮（被暂停、弹窗、演出效果挡住），就先停止触控，又看到了接着打（是演出挡住了，这首歌之后再看不到也照常触控）；连续 `play.guard_abort_s` 秒（默认 10）都看不到就结束这一局：游戏暂停了就从头重试（次数算在 `loop.sync_retries` 里），闪退等由导航重新找回画面。`guard_lost_s` 设为 0 关闭这项检查
- 首音符同步失败、生命值降到 0 时，暂停后点「重试」重新开始这一局，不浪费 LB
- 画面一直认不出时，每 30 秒检查一次游戏进程；游戏闪退了就经 adb 重新启动，从标题画面重新登录。连续重启最多 2 次，回到主页后重新计数
- 没见过、只有「OK」的提示弹窗（上面没有取消、确定、购买、星钻之类的字）直接点 OK 继续，日志里会记下弹窗上的文字，截图存在 `debug/nav`
- 右上角有「跳过」的全屏演出（比如角色生日演出）点跳过；之后接着放的故事打开右上角菜单点 SKIP 跳过
- 保底：认不出的画面 60 秒一点没变，或者一直在动但 150 秒都认不出（加载、下载中不算），就重启游戏重新登录，和闪退共用上面的重启次数；重启次数用完还卡住才停下
- 游戏连续运行十几个小时后会越来越卡（从 60fps 掉到 30 多），同步失败、整首对不上。连续打歌时最近 5 次同步测到的出帧率（中位数）低于 `loop.min_fps`（默认 50，0 为不检查）就在换歌前重启游戏；重启后还是这么低（电脑本身忙不过来、模拟器限了帧率）就不再因此重启。重启后会等游戏把画面准备好（按包名查得到画面的 display）再继续，不会截到模拟器桌面。界面里的全局选项「卡顿时重启游戏」关掉时等同于设为 0
- 服务器维护（「服务器正在维护中」页面）：挂机每 10 分钟点「返回标题画面」重新登录看一次，开服后接着挂机（开了「推送到手机」时，开始等和开服时各推送一条）；其他任务直接失败
- 游戏更新：登录时的「数据下载」（追加的游戏数据）自动点 OK 下载；「检测到新版本」（要去应用商店更新安装包）不会自动点，任务直接失败，挂机也会停下，需要自己更新游戏后再开始
- 电脑内存不够：电脑还能提交的内存（任务管理器「性能 › 内存」里的「已提交」）剩不到 1 GB 时，日志里提醒一次；演奏进程因分配不到内存退出时，界面上会写明是电脑内存不足。请关掉占内存多的程序或重启电脑后再开始，任务管理器「详细信息」按「提交大小」排序能看到是哪个程序占的

## 工作原理（简述）

1. **导航**：截图 → OCR → 按文字与位置判断当前画面 → 点击按钮。按钮优先按文字精确定位，找不到时用固定坐标
2. **识曲**：乐队确认页 OCR 出曲名，模糊匹配谱面站与国际服的多语言曲名，得到 musicId
3. **同步**：点击开始后，等画面静止，检测第一个音符出现在它所在轨道的上方，跟踪它的前沿。音符逼近判定线满足 `y - y_h ∝ exp(t/τ)`，拟合后外推到达时刻，由此推出歌曲的零点
4. **演奏**：谱面转换成触控手势（点击、滑动、长条、追踪），经 minitouch 注入触控（备选 MuMu IPC），高精度计时器按时发送。按游戏的判定表避开相邻音符互相「认领」触点：同时横滑的邻居错开起点，会被之后的点击认领的上划 / 追踪提前按下
5. **结算**：读取判定数与 FAST/SLOW，记录结果并修正偏移
