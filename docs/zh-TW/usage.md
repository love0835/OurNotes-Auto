# 使用說明

[README](../../README.zh-TW.md) 之外的詳細說明：各任務的細節、遊戲內設定、自動修正、擬人化、發生意外時的處理、執行時檔案和運作原理。命令列用法見[命令列](cli.md)。

## 環境需求

- Windows，MuMu 模擬器 12（本專案在 MuMu 6.6.x、Android 15 實例上測試）
- 模擬器解析度 **1280×720**（其他 16:9 解析度會依比例換算，但未經充分測試；不是 16:9 的啟動時會報錯），幀率不低於 60（同步參數依 60 幀截圖調整）
- 遊戲：國際服（套件名稱 `com.bilibili.sirius.official`；Google Play 版是 `com.bilibili.sirius`，會自動辨識），遊戲語言為简体中文、繁體中文、English 或 한국어；或日服（套件名稱 `com.bushiroad.sirius`）。導航靠 OCR 辨識介面上的文字，其他服認不出按鈕。한국어要把「遊戲語言」選成 한국어：第一次執行時會自動下載韓文文字辨識模型（約 10 MB），之後每次會多載入它（兩個模型一起辨識，每次辨識會慢一些）；不選 한국어 就不會下載也不會載入
- 日服：把「遊戲語言」選成「日本語（日服）」，啟動遊戲等任務就會操作日服用戶端（不用另外下載辨識模型）。日服用戶端要從 Google Play 安裝，直接裝 APK 打不開。切換帳號只能用於國際服。T.G.W CARD 和商店要先在遊戲裡自己做一次年齡確認，沒做時領取日常會跳過 T.G.W CARD。日服只驗證過自由演出、AP補完和領取日常，挑戰演出還沒在日服試過
- 遊戲內設定見[遊戲內設定](#遊戲內設定)
- 能連上譜面站 `assets.bdon.moe` 與曲名 API `haneoka.org`（檢查更新、自動更新會另外連到 `github.com`，可以關掉）。瀏覽器打得開、這裡一直下載失敗（日誌裡「下載失敗…遠端主機已強制關閉一個現存的連線」）時，在全域選項「網路代理」裡填代理軟體的 HTTP 連接埠（如 `127.0.0.1:7890`），命令列設環境變數 `HTTPS_PROXY`
- 發布包：兩種介面都需要 [VC++ 2015–2022 可轉散發套件](https://aka.ms/vs/17/release/vc_redist.x64.exe)（MaaFramework 的相依元件）；MFAA 另外需要 .NET 10 桌面執行階段（包裡的 `DependencySetup_依赖库安装_win.bat` 可一鍵安裝它和 VC++ 可轉散發套件），MXU 需要 WebView2（Windows 10/11 通常已內建）。包裡內附 Python 執行環境、MaaFramework 與 OCR 模型，譜面在執行時從譜面站下載。各元件的授權條款見 [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md)
- 從原始碼執行：Python ≥ 3.11，見[命令列](cli.md)

## 連接模擬器

連線設定裡選「MuMu 模擬器」，再選要用的模擬器實例。MuMu 12 第 n 個實例的 adb 位址是 `127.0.0.1:16384+32n`，例如第 0 個是 16384，第 1 個是 16416。截圖和觸控走 MuMu 的 API，安裝目錄由 adb 路徑推得，所以目前只支援 MuMu 12。

## 任務

遊戲停在主畫面或自由演出選曲頁即可；遊戲沒開也行，除了「跟打」「開啟統計視窗」「推播測試」，其餘任務都會先啟動它（已經開著就直接用），再等過標題畫面、登入報酬和公告進入遊戲。

| 任務 | 作用 |
|---|---|
| 啟動遊戲 | 遊戲沒在執行時啟動它，點掉標題畫面、登入報酬和公告，進入主畫面。其他任務（除了「跟打」「開啟統計視窗」「推播測試」）都會先做這一步，不用單獨勾選 |
| 切換帳號 | 只限國際服。登出目前的 B 站帳號，從遊戲的登入紀錄裡選填寫的帳號登入（不用輸入密碼），然後進入主畫面；已經在遊戲裡時先重新啟動遊戲回到標題畫面。帳號名稱填登入紀錄裡顯示的名字，寫一部分也行，但只能對應到一個帳號。只能切換到登入紀錄裡有的帳號，新帳號請先在遊戲裡手動登入一次。多個帳號輪流打：任務列表裡排成「切換帳號（A）→ 其他任務 → 切換帳號（B）→ 其他任務」。用戶中心的「註銷」、登入紀錄每一列右邊的 ⓧ 都不會點。演奏紀錄、統計與成就目前不分帳號 |
| 重複刷歌 | 在自由演出裡連續演奏，可選擇選曲方式（目前曲目 / 隨機 / 優先未 AP / 指定歌單）、難度、局數、每局消耗的 LB。難度選「優先高難度」時，「優先未 AP」從 EXPERT 到 EASY 依序補，都補完了就以 EXPERT 隨機；其他選曲方式以 EXPERT 打 |
| 清體力 | 連續演奏到 LIVE BOOST 用完（每局前看持有數，為 0 就結束），不用星鑽。升級會回滿 LB，所以局數可能比預計的多 |
| 掛機 | 和清體力一樣打到 LB 用完，然後停在樂團確認頁，依右上角的回復倒數計時等 LB 回復到每局消耗數，再接著打（LB 每 30 分鐘回復 1 個，消耗 3 時約 90 分鐘一局）。每局消耗選 0 時不等 LB：每局前看持有數，有 LB 就消耗 1 個，用完了就改為消耗 0 接著打，回復出來再消耗，一直打歌。一直執行到手動停止或打滿局數；等待時遇到日期變更會重新登入，遇到伺服器維護則每 10 分鐘看一次，開服後接著掛機。選項「定時收穫」（預設開，間隔 4 小時）：開始時先領一次錄音室練習，之後每隔設定的小時數（1~12）在兩局之間或等 LB 時回主畫面再領一次，領完回來接著掛機（錄音室練習最多累計 12 小時，超過後效率降到 30%）；沒領成的過 30 分鐘再領。選項「每天領取日常」（預設開，22:30）：每天到設定的時間（電腦的本地時間）同樣回主畫面領一次任務、任務通行證、期間限定任務、新手任務、T.G.W CARD、免費轉蛋和禮物盒，沒領全的過 10 分鐘再領一遍（一天最多 3 遍）。任務列表裡的「領取日常」只在掛機前跑一次，掛機跨日後靠這個領；遊戲每天 23:00 日期變更，領取時間要早於 23:00 才領得到當天的。不用星鑽。它不會自己結束，請放在任務列表的最後 |
| AP補完 | 把所選難度（EXPERT / HARD / NORMAL / EASY）裡還沒 ALL PERFECT 的歌打到 AP。會暫時把選曲頁切到「全部」分類、篩選「未ALL PERFECT」，正常結束後改回原樣。同一首打了「每首最多嘗試」次還沒 AP 就不再打；其中每次都沒打完（同步失敗、生命值歸零）的譜面會記下來，3 天內 AP補完和「優先沒 AP 的歌」都不再打它（多半是遊戲更新後譜面對不上，過幾天再試） |
| 挑戰演出 | 只在部分活動期間開放（沒開放時報錯結束）。從「演出TOP」進「挑戰演出」連續演奏，每局消耗挑戰pt（CP）而不是 LB，打到 CP 不夠一局為止。持有數不夠所選的消耗時遊戲不讓點 OK（提示「挑戰pt不足。」），這時點「取消」後停下，不會一直點 OK 到逾時。選項「每局消耗挑戰pt」預設 200（×1，最省、能多打幾輪），也可選 400 / 800 / 1600（報酬 ×2 / ×4 / ×8）或不改遊戲裡的設定；第一局前在「CP 設定」裡選好並核對單選按鈕後才點 OK。選曲方式「輪流打每首歌」（預設）每局換到列表裡的下一首，到底了就回到第一首；「優先打沒 AP 的歌」每局開始前逐首看所選難度有沒有 ALL PERFECT，先打沒 AP 的（同一首最多打 3 次），都 AP 了再輪流打（難度選「優先高難度」時依 EXPERT → HARD → NORMAL → EASY 依序補）；也可以一直打目前選中的歌。樂團確認頁的「跳過」不會點 |
| 跟打 | 只幫你打歌，其他都自己點：自己選歌、點 LIVE START 開始演出，畫面進入載入時就開始同步（和其他演奏任務一樣穿過載入畫面取基準），演奏畫面一出來就自動打歌。曲目在樂團確認頁辨識，所以要經過樂團確認頁（辨識不出、譜面站沒有這首時這一首不打，日誌裡有說明）；難度按畫面上的讀，讀不出時按等級判斷。自由演出、挑戰演出和協力演出都可以（協力演出在「選擇難度」頁辨識曲目：難度看下面那行裡哪一格的底色是難度色（選中那格的底色比別的鮮豔一倍，比辨識封面左邊那個斜排的大字穩），等級取那一格難度名正上方的數字；難度就在這一頁上選，改了會重新辨識（連著幾次分不出選中哪一格就不打這一局，免得拿改之前那個難度的譜面打）；按下「準備完成」後等其他玩家、載入這段最多等 160 秒（等別人準備全看別人，所以比單人的 40 秒寬得多，見 sync.multi_wait_s），太久這一局就不打。協力不能暫停，右上角沒有暫停按鈕，所以不做演奏畫面確認、演奏中也不檢查，打得對不對只能靠同步結果判斷）。LIVE CLEAR、結算頁翻頁、彈窗都等你自己點，只在結算頁上點一下 ⇄ 讀 FAST/SLOW，和其他任務一樣記錄成績、修正 offset（讀完判定數之前就點了下一步，這一局不記錄；讀完判定數、還沒讀 FAST/SLOW 時點了，只記判定數）。演奏中暫停後點重試並確認，會從頭接著打這一首；點繼續接不上，這一局不打了。同步沒跟上時這一局也不打，可以自己暫停重試。不啟動、不重啟遊戲，一直執行到手動停止 |
| 領取日常 | 依序領取錄音室練習（收穫）、任務、通行證任務與 PASS 普通檔（同時有幾個通行證時逐個領）、期間限定任務、新手任務、T.G.W CARD、免費轉蛋、禮物盒的報酬，每項可單獨關掉。只點亮著的「一併領取」和報酬彈窗的 OK；T.G.W CARD 領每日積分、每日報酬和商店專享商品目錄裡價格寫著「免費」的商品，要星鑽的不點；免費轉蛋（預設開）只在主畫面轉蛋入口上有免費角標時做，按鈕寫著「免費」「1次」、確認視窗寫著消耗 0 個星鑽才點，轉蛋演出點 SKIP，結算後只點回到轉蛋首頁（不點「再次轉蛋」、付費轉蛋和廣告），結果截圖存在 `data/recruit/`，MXU 的日誌裡直接顯示，前後核對星鑽數沒變（目前只在簡體中文介面實測過）；不認得的彈窗不點，報錯停下。打完歌後每日任務才會滿，所以排在演奏任務後面。可選「看故事（跳過）」（預設關）：把沒看過的樂團故事、側寫故事、羈絆故事逐話跳過，解鎖樂曲、領看完的報酬，每話第一次看要下載資料（無語音，樂團故事約 30MB）。可選「活動故事（跳過）」（預設關）：限時活動期間從「演出TOP」→「活動」進活動頁（同時有好幾個活動、先彈出「活動選擇」時點舉辦中的那個），把「活動故事」裡沒看過的活動故事、側寫故事逐話跳過；沒有限時活動時跳過這項 |
| 開啟統計視窗 | 開啟「統計與成就」視窗（見下面的「統計與成就」；換套件前在視窗裡匯出紀錄，見「備份與還原」），並在日誌裡列出演奏紀錄（各難度 AP 過的譜面、打過還沒 AP 的譜面、最近 10 局）。不操作模擬器 |
| 推播測試 | 依全域選項「推播到手機」發一則測試訊息（見下面的「推播到手機」）。不操作模擬器 |

### LB 不足時用道具補充

重複刷歌、清體力、掛機、AP補完都有選項「LB 不足時用道具補充」（預設關）：每局開始前 LB 持有數少於每局消耗數時，從「消耗LB」→「回復」進去，只在「道具」頁用 LIVE BOOST飲料補足這一局（先用小型 +1，不夠再用 +10），核對選中的數量、回復預覽和確認彈窗上的數字都對得上才點 OK；不在「道具」頁或有任何對不上就點取消、本次不再補充。絕不用星鑽、不看廣告。

子選項「最多補充」是本次執行最多補充的 LB 數，0 為直到飲料用完。飲料用完後依原來的方式繼續（清體力就此結束，掛機開始等回復）。需要把每局消耗 LB 設為 1~5 或「自動」。

### 每局消耗 LB：4、5 與「自動」

「每局消耗 LB」可選 0~5（重複刷歌、AP補完還可選不改遊戲裡的設定）。4、5 要 T.G.W CARD 10 級、14 級解鎖；沒解鎖時依「消耗LB」彈窗裡能選的最大值，日誌裡會提示。

選「自動（依持有數選）」時每局開始前開啟「消耗LB」彈窗，依當時的持有數選：

- 一般選能選的最大消耗（沒解鎖 4、5 時為 3）；持有數不夠就選持有數，把剩下的全部消耗掉。
- 「全部消耗」（一局最多消耗 10 個，持有 4 個以上才能用；每天能用幾次看月卡，例如最高檔月卡每天 5 次）在下面兩種情況下使用：持有 10 個以上；或者用它比一局局消耗能少打 2 局以上（例如持有 7 個、最大消耗 3 時，一局局消耗要打 3 局，全部消耗只要 1 局）。
- 「全部消耗」用到今天的次數用完為止（在遊戲裡手動用掉的也算）：彈窗上顯示「今日次數已用完」、或者今天用過之後再勾不上時，記在 `data/state.json`（用「切換帳號」輪流打多個帳號時依帳號分開記），當天（遊戲日期，每天 23:00 變更）不再檢查。
- 清體力選自動時打到 LB 用完就結束；掛機選自動時 LB 用完後每回復 1 個就消耗掉，不等存夠。掛機選 0 時仍是原來的「有就消耗 1 個，沒有就消耗 0」。

### 使用跳過

清體力、掛機有選項「使用跳過」（預設關）：每局前先點樂團確認頁的「跳過」，在確認彈窗裡依「每局消耗 LB」選好消耗（自動時同樣會用「全部消耗」）後跳過目前選中的歌，每天的跳過次數用完了再演奏。跳過不算在局數裡，結束時的日誌裡列出跳過了幾次。

- 只在這一局會消耗 LB 時跳過（每局消耗 1~5 或自動；掛機選 0 時有 LB 才跳過，消耗 1 個）。LB 用完了不點跳過（確認彈窗裡看到持有 0 時點「關閉」），依原來的方式繼續。
- 挑戰演出的「跳過」不會點。

### 其他選項

- 需要調整預設值以外的參數（如時間偏移）時，把 [config.example.yaml](../../config.example.yaml) 複製為解壓縮目錄裡的 `config.yaml` 再修改。介面裡的選項優先於它。
- 介面日誌預設只顯示進度和結果。開啟全域選項「偵錯日誌」後，同步、譜面、觸控等細節也會顯示；完整日誌一律寫在 `data/ournotes.log`。
- 全域選項「檢查更新」「自動更新」預設開啟：任務開始時查 GitHub 上有沒有新發布的版本（MFAA 打開介面、連上模擬器時也按上次執行任務時的選項查一次），有就在背景下載，進度和結果在任務結束時的日誌裡提示。
  - 只改了演奏部分時，沒有任務執行就直接換上，下個任務用新版本；不限次數的掛機會在兩首歌之間暫停一下，換好後自動繼續。
  - 改了介面要讀的內容（任務、選項、介面文字）時，要重新啟動介面：沒有任務執行、介面閒置 2 分鐘後自動關掉介面，換好後重新打開（不會自動開始任務）。介面設成打開就自動開始任務時（MXU 的「手動啟動時也自動執行」，MFAA 帶「啟動腳本」的啟動方式）不替你重新啟動，關掉介面後自動換上。
  - 介面程式、Python、相依套件或文字辨識模型變了時，下載整個壓縮檔替換，時機同上。`config/`、`data/`、`cache/`、`debug/` 和介面自己的設定不動。
  - 換之前的檔案備份在 `cache/update/backup/`；新版本啟動不了會自動換回原來的版本，在日誌裡提示，這個版本不再自動更新。如果還原也失敗，會保留備份並停止任務和自動更新；請按日誌手動恢復，或把發佈包解壓到新目錄後再執行。
  - 關掉「自動更新」只提示有新版本，要手動下載新的壓縮檔。沒有「自動更新」選項的舊版本要手動下載一次。

### 統計與成就

累計執行時長、演奏數據（每天的局數、各難度、各譜面的戰績）和成就（有幾個是隱藏的），每局後更新；有這個功能之前的執行時長按演奏紀錄估算。只統計本工具打的局，頁面目前只有簡體中文。在這幾個地方看：

- 「統計與成就」視窗：執行任務「開啟統計視窗」，或者雙擊套件目錄裡的「统计与成就」捷徑（從介面執行過任意一個任務後自動建好）。打完一局自動重新整理，解鎖成就時跳出提示；正在執行的任務在概覽最上面顯示正在做什麼（演奏哪首歌、下一個 LB 還要多久恢復等），幾秒更新一次；已經開著時切到前面。用 Edge 的應用程式模式開啟（沒有 Edge 時用 Chrome，都沒有時用預設瀏覽器）。
- MXU：「設定」頁最上面的「統計與成就」卡片，重新開啟設定可以重新整理；卡片底部的「在浏览器里打开」用預設瀏覽器開啟和視窗裡一樣的頁面（要開著 MXU 內建的 Web 服務，預設開著）。
- MFAA：任務「開啟統計視窗」的說明，點一下別的任務再點回來可以重新整理；說明最後有開啟視窗的連結。

任務結束時日誌裡寫一行本次執行的時長和累計數據，解鎖成就時寫一行「★ 解锁成就」。

### 備份與還原

演奏紀錄、執行紀錄、成就和學到的時間偏移都在套件目錄的 `data` 裡，刪掉套件、換成新下載的完整套件時會跟著不見。換套件前在「統計與成就」視窗右上角點「备份与恢复」匯出一份（MXU 設定頁卡片的「在浏览器里打开」開啟的頁面不能匯出、匯入，要在視窗裡做）：

- 「导出备份」：選好存到哪裡，存成一個 `OurNotes-Auto-backup-<時間>.zip`。放在套件目錄外面（如「文件」），刪掉舊的套件也還在。
- 「导入」：在新的套件裡開啟「統計與成就」視窗，點「选择备份文件」選匯出的 zip。沒匯出過、舊的套件還在時，展開「没导出过？从旧的包目录导入」，填舊的套件目錄（或它的 `data` 資料夾）點「读取」。先顯示會匯入多少，點「确认导入」才匯入，匯入完頁面自動重新整理。
  - 是合併，不是覆蓋：這個套件裡已有的紀錄一行不動，只補上沒有的，同一局、同一次執行不會重複；成就按早的解鎖時間。同一份備份再匯入一次不會有改動。
  - 學到的時間偏移只在這個套件還沒學過時匯入。全域偏移跟電腦、模擬器有關，只在匯出的那台電腦上匯入；按譜面的偏移在別的電腦上也匯入。
  - 要改的檔案先複製到 `data/import_backup/<時間>`（留最近 5 次），匯入的結果不對時可以從那裡拿回來。
  - 有打歌任務在執行時不能匯入（它們也在寫演奏紀錄），先停止。匯入時開始的任務會等匯入完再開始。
  - 新版本匯出的備份，可能要先把這個套件更新到那個版本才能匯入（會提示）。
- 轉蛋截圖（`data/recruit`）和 `config.yaml` 不在備份裡，要的話自己複製。新的套件還沒打過歌時，直接把舊的套件的 `data` 資料夾複製過去也一樣。

### 推播到手機

全域選項「推播到手機」選好推播方式、填好「推播位址」後，這幾種情況會發一則訊息到手機：

- 打歌任務（重複刷歌、清體力、掛機、AP補完、挑戰演出）完成：打了幾局、FC / AP / 失敗各幾局、用時多久。領取日常完成時也推播一則。
- 任務出錯結束：出了什麼錯（日誌裡最後一則錯誤）和用時。跟打、啟動遊戲、切換帳號只在出錯時推播（跟打一直執行到手動停止，沒有「完成」）；開啟統計視窗不推播。
- 掛機遇到伺服器維護：開始等待時推播一則，開服、接著掛機時再推播一則。

手動停止的任務不推播。「推播哪些訊息」選「只推播出錯和伺服器維護」時不推播完成。推播訊息目前是簡體中文。

| 推播方式 | 設定 |
|---|---|
| ntfy | 免費，不用註冊。手機裝 ntfy App（Android、iOS），訂閱一個別人猜不到的主題名稱（字母、數字、- 和 _），把主題名稱填進「推播位址」。自架的 ntfy 服務填完整網址，如 `https://ntfy.example.com/主題名稱` |
| Server醬（微信） | 推播到微信。在 [sct.ftqq.com](https://sct.ftqq.com/) 用微信掃碼登入，複製 SendKey 填進「推播位址」（Server醬³ 的 SendKey 也可以）。免費版每天能推播的則數有限，可以只推播出錯和伺服器維護 |
| Bark（iPhone） | 推播到 iPhone。在 App Store 裝 Bark，打開後複製它給的網址（如 `https://api.day.app/你的key/`，後面帶著範例的推播內容也可以）填進「推播位址」，也可以只填 key。自架的 Bark 伺服器填 `https://伺服器位址/你的key`。出錯的訊息是時效性通知，開著專注模式也會提醒 |
| webhook | 把訊息以 JSON POST 到「推播位址」填的網址：`event`（`done` / `error` / `maintenance` / `test`）、`title`、`text`、`time`（Unix 時間戳），用來接自己的機器人或其他推播服務 |

- 設好後執行任務「推播測試」（不操作模擬器），看看手機收不收得到；沒收到時日誌裡寫著原因。
- 「推播位址」等於密碼：別人拿到就能發訊息給你，ntfy 的主題還能被別人訂閱、看到你的訊息。別給別人看，日誌裡也不會記。
- 推播失敗（網路不通、位址填錯、超過 Server醬的每日則數）只在日誌裡記一則警告，任務照常執行。
- 命令列執行時在 `config.yaml` 的 `notify` 裡設定（見 [config.example.yaml](../../config.example.yaml)），用 `ournotes-auto notify-test` 測試。

## 遊戲內設定

| 設定 | 建議 | 說明 |
|---|---|---|
| 節奏圖示速度 | **5.00**（必須） | 同步參數 `play.sync.tau_s = 0.835` 是在 5.00 下測的。每局開始前會從演出前選項設定彈窗讀出流速核對，不一致只在日誌裡警告、不會停下：其他流速仍能同步，但按鍵時機整體偏移。改回 5.00，或執行 `calibrate motion` 重新測量（另見[擬人化](#擬人化可選預設關閉)一節的流速要求） |
| MV / 背景 | 關閉，或換成較暗、不會動的背景（必須） | 開局要等畫面靜止後再追蹤第一個音符。背景一直在動時最多等 4 秒就開始追蹤，亮的背景還會混進來，導致同步失敗或不準 |
| 小節線顯示（詳情 → 節奏圖示設定） | 開或關都可以 | 開局追蹤第一個音符時，會認出橫貫軌道的小節線並跳過。0.1.3 及更早的版本會把比第一個音符先落下的小節線當成第一個音符，整局提前、很快生命值歸零，用這些版本時請關掉 |
| 特效、演出等級 | 不強制，電腦配備較弱時建議調低 | 只在開局幾秒看畫面（這時還沒有打擊特效），彩色特效會被過濾；之後依譜面演奏，只看右上角的暫停按鈕。但目前只在調低的設定下測過，高特效下可能有亮白色的開場特效混進追蹤區，或全螢幕演出連續遮住暫停按鈕超過 2 秒被當成離開演奏畫面而停止觸控。調低還能讓模擬器幀率更穩 |
| 樂團確認頁「消耗LB」 | 用設定項 `game.lb_cost`（0~5）或 `game.lb_auto` 自動設定 | 第一局前自動開啟彈窗選好並核對，遊戲會記住。0 不消耗 LB（LIVE START 上顯示「n ▸ n」）。LB 不夠時遊戲會消耗剩餘全部；彈出「LIVE BOOST回復」（道具/星鑽/廣告）時只點取消，該局改為 0（開了 `game.lb_refill` 時先用道具裡的 LIVE BOOST飲料補充，見[上文](#lb-不足時用道具補充)）。留空（null）則不改遊戲裡的設定 |

換電腦、換模擬器實例或重新安裝後，先用低難度打一兩首，看日誌裡有沒有同步失敗或流速警告。不同電腦的截圖、觸控延遲不一樣，不用手動調整：自動修正會逐局調整時間偏移，每局最多 1ms（見[時間偏移與自動修正](#時間偏移與自動修正)）。

## 時間偏移與自動修正

`play.offset_ms` 是全域時間偏移，正值表示整體更晚按下，用來補償截圖、輸入、渲染帶來的延遲。MuMu 上實測約 -16ms 時判定置中。

每局結束後，程式讀取結算頁的 FAST/SLOW。FAST 多就往後推，SLOW 多就往前拉，把學到的偏移存進 `data/state.json`（與設定裡的 `offset_ms` 疊加）。以下情況只記錄、不修正：執行不穩定（遲到的批次多），或者 GOOD/BAD/MISS 過多（多半是同步到了錯誤的音符）。

### 按譜面修正

有的譜面一直偏 FAST 或偏 SLOW（實測 56 張打過 4 局以上的譜面裡 22 張平均偏差很大），全域偏移被它們來回拉。開啟 `play.auto_tune.per_chart`（預設開）後，某張譜面最近 `chart_plays` 局（預設 3）的偏差方向和全域近況相反、且平均絕對值不小於 `chart_threshold`（預設 0.4）時，這段偏差算這張譜面自己的：只調它自己的偏移（每張譜面不超過 ±`chart_max_ms`，預設 ±10ms），這一局不動全域偏移。譜面偏移按流速分開記，換了流速要從頭學。

用 `ournotes-auto records` 看時，學過的譜面偏移會一起列出來（偏得多的在前）；`ournotes-auto records --clear-chart-offsets` 可清除所有譜面偏移（全域學習值不變），譜面大改（例如遊戲更新換了譜面）後清一次再重新學。

## 擬人化（可選，預設關閉）

讓結果不那麼整齊。介面裡在全域選項中，命令列用 `--set` 修改：

| 設定項 | 介面選項 | 作用 |
|---|---|---|
| `play.touch.great_ratio` | 隨機 GREAT（1% / 3% / 5%） | 依判定總數的這個比例，挑前後沒有其他音符緊鄰的一般點擊，提前或延後 64~69ms 打成 GREAT（單局同步誤差偏大時其中一部分會變成 PERFECT 或 GOOD，GOOD 不會斷連擊）。選曲方式為 `ap` / `ap_first` 時不生效。開啟後自動修正偏移時不計 GREAT 的 FAST/SLOW |
| `play.touch.jitter_ms` | 時機偏移（±8 / ±16ms） | 按下時刻隨時間緩慢漂移（最多 ± 設定值），另加每個手勢最多 ±3ms 的獨立抖動。上限 20ms |
| `play.touch.position_jitter` | 觸控位置隨機 | 觸控點在音符寬度內隨機橫移，並上下小幅挪動。不會挪進旁邊點擊類音符的判定區（否則按下可能被它認領），按住的長條也不會挪進同時按住的另一個長條的判定區。取值 0~1 為幅度，介面開關開啟時為 1 |

例：`ournotes-auto --set play.touch.great_ratio=0.03 --set play.touch.jitter_ms=8 --set play.touch.position_jitter=1 run`

開了「隨機 GREAT」時請把遊戲內節奏圖示速度保持在校準過的那個值（預設 5.00）。GREAT 的判定區間是 ±83ms，
故意打的 GREAT 落在偏 64~69ms 處，留給整體偏移的餘裕只有十幾毫秒：流速不是校準時用的值，
偏移就可能超出去，延後打的 GREAT 變成 GOOD（連擊還在，但結果不對）。
流速越快，首音符的追蹤時間越短（5.00 約 1.8 秒、10.00 約 0.45 秒），單局內的同步誤差也越難被平均掉，
所以這個餘裕在 10.00 下最緊。

## 意外狀況

- 演奏中連續 `play.guard_lost_s` 秒（預設 2）看不到右上角的暫停按鈕（被暫停、彈窗、演出效果擋住），就先停止觸控，又看到了接著打（是演出擋住了，這首歌之後再看不到也照常觸控）；連續 `play.guard_abort_s` 秒（預設 10）都看不到就結束這一局：遊戲暫停了就從頭重試（次數算在 `loop.sync_retries` 裡），閃退等由導航重新找回畫面。`guard_lost_s` 設為 0 關閉這項檢查
- 首音符同步失敗、生命值降到 0 時，暫停後點「重試」重新開始這一局，不浪費 LB
- 畫面一直認不出時，每 30 秒檢查一次遊戲處理程序；遊戲閃退了就經 adb 重新啟動，從標題畫面重新登入。連續重新啟動最多 2 次，回到主頁後重新計數
- 沒見過、只有「OK」的提示彈窗（上面沒有取消、確定、購買、星鑽之類的字）直接點 OK 繼續，日誌裡會記下彈窗上的文字，截圖存在 `debug/nav`
- 右上角有「跳過」的全螢幕演出（例如角色生日演出）點跳過；之後接著播放的故事開啟右上角選單點 SKIP 跳過
- 保底：認不出的畫面 60 秒完全沒變，或者一直在動但 150 秒都認不出（載入、下載中不算），就重新啟動遊戲重新登入，和閃退共用上面的重新啟動次數；重新啟動次數用完還卡住才停下
- 遊戲連續執行十幾個小時後會越來越卡（從 60fps 掉到 30 多），同步失敗、整首對不上。連續打歌時最近 5 次同步測到的出幀率（中位數）低於 `loop.min_fps`（預設 50，0 為不檢查）就在換歌前重新啟動遊戲；重新啟動後還是這麼低（電腦本身忙不過來、模擬器限制了幀率）就不再因此重新啟動。重新啟動後會等遊戲把畫面準備好（按套件名稱查得到畫面的 display）再繼續，不會截到模擬器桌面。介面裡的全域選項「卡頓時重新啟動遊戲」關掉時等同於設為 0
- 伺服器維護（「伺服器正在維護中」頁面）：掛機每 10 分鐘點「返回標題畫面」重新登入看一次，開服後接著掛機（開了「推播到手機」時，開始等待和開服時各推播一則）；其他任務直接失敗
- 遊戲更新：登入時的「下載資料」（追加的遊戲資料）自動點 OK 下載；「檢測到新版本」（要去應用程式商店更新安裝檔）不會自動點，任務直接失敗，掛機也會停下，需要自己更新遊戲後再開始
- 電腦記憶體不夠：電腦還能認可的記憶體（工作管理員「效能 › 記憶體」裡的「已認可」）剩不到 1 GB 時，日誌裡提醒一次；演奏程序因配置不到記憶體而結束時，介面上會寫明是電腦記憶體不足。請關掉佔記憶體多的程式或重新開機後再開始，工作管理員「詳細資料」按「認可大小」排序能看到是哪個程式佔的

## 運作原理（簡述）

1. **導航**：截圖 → OCR → 依文字與位置判斷目前畫面 → 點擊按鈕。按鈕優先依文字精確定位，找不到時用固定座標
2. **識曲**：樂團確認頁 OCR 出曲名，模糊比對譜面站與國際服的多語言曲名，得到 musicId
3. **同步**：點擊開始後，等畫面靜止，偵測第一個音符出現在它所在軌道的上方，追蹤它的前緣。音符逼近判定線時滿足 `y - y_h ∝ exp(t/τ)`，擬合後外推到達時刻，由此推出歌曲的零點
4. **演奏**：譜面轉換成觸控手勢（點擊、滑動、長條、追蹤），經 minitouch 注入觸控（備選 MuMu IPC），高精度計時器準時傳送。依遊戲的判定表避開相鄰音符互相「認領」觸控點：同時橫滑的相鄰音符錯開起點，會被之後的點擊認領的上滑 / 追蹤提前按下
5. **結算**：讀取判定數與 FAST/SLOW，記錄結果並修正偏移
