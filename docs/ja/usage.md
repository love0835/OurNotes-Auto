# 使い方

[README](../../README.ja.md) に書ききれない詳しい説明です：各タスクの詳細、ゲーム内設定、自動補正、人間らしさ機能、トラブル時の動作、実行時ファイルと仕組み。コマンドラインでの使い方は[コマンドライン](cli.md)を参照してください。

## 動作環境

- Windows、MuMu エミュレーター 12（本プロジェクトは MuMu 6.6.x、Android 15 インスタンスでテストしています）
- エミュレーターの解像度は **1280×720**（他の 16:9 解像度も比率で換算しますが、十分にはテストしていません。16:9 以外は起動時にエラーになります）、フレームレートは 60 以上（同期パラメータは 60 fps のスクリーンショットに合わせて調整しています）
- ゲーム：国際版（パッケージ名 `com.bilibili.sirius.official`。Google Play 版は `com.bilibili.sirius` で、自動で判別します）、ゲーム言語は 简体中文、繁體中文、English、한국어 のいずれか。または日本版（パッケージ名 `com.bushiroad.sirius`）。ナビゲーションは OCR で画面上の文字を認識して行うため、他のサーバーではボタンを認識できません。한국어 の場合は「ゲーム言語」を 한국어 にしてください：初回実行時に韓国語の文字認識モデル（約 10 MB）を自動でダウンロードし、以降は毎回それも追加で読み込みます（2 つのモデルで一緒に認識するため、認識が毎回少し遅くなります）。한국어 を選ばなければ、ダウンロードも読み込みもしません
- 日本版：「ゲーム言語」を「日本語（日本版）」にすると、ゲーム起動などのタスクが日本版のクライアントを操作します（認識モデルの追加ダウンロードはありません）。日本版のクライアントは Google Play からインストールする必要があり、APK を直接インストールしたものは起動できません。アカウント切替は国際版でのみ使えます。T.G.W CARD とショップは、先にゲーム内で一度ご自身で年齢確認をしてください。未確認の間、デイリー受け取りは T.G.W CARD を飛ばします。日本版で検証済みなのはフリーライブ、AP埋め、デイリー受け取りのみで、チャレンジライブはまだ試していません
- ゲーム内設定は[ゲーム内設定](#ゲーム内設定)を参照
- 譜面サイト `assets.bdon.moe` と曲名 API `haneoka.org` にアクセスできること（アップデート確認と自動アップデートでは別途 `github.com` にアクセスします。オフにできます）。ブラウザでは開けるのにここでダウンロードが失敗し続ける（ログに「ダウンロード失敗…既存の接続はリモート ホストに強制的に切断されました」）場合は、グローバル設定「ネットワークプロキシ」にプロキシソフトの HTTP ポート（例：`127.0.0.1:7890`）を入力してください。コマンドラインでは環境変数 `HTTPS_PROXY` を設定します
- リリースパッケージ：どちらの UI にも [VC++ 2015–2022 ランタイム](https://aka.ms/vs/17/release/vc_redist.x64.exe)（MaaFramework が依存）が必要です。MFAA には別途 .NET 10 デスクトップランタイム（同梱の `DependencySetup_依赖库安装_win.bat` で VC++ ランタイムと一緒にワンクリックでインストール可能）、MXU には WebView2（Windows 10/11 には通常プリインストール済み）が必要です。パッケージには Python ランタイム、MaaFramework、OCR モデルが同梱されており、譜面は実行時に譜面サイトからダウンロードします。各コンポーネントのライセンスは [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md) を参照してください
- ソースから実行する場合：Python ≥ 3.11。[コマンドライン](cli.md)を参照

## エミュレーターへの接続

接続設定で「MuMu エミュレーター」を選び、使うエミュレーターのインスタンスを選びます。MuMu 12 の n 番目のインスタンスの adb アドレスは `127.0.0.1:16384+32n` で、たとえば 0 番目は 16384、1 番目は 16416 です。スクリーンショットとタッチは MuMu のインターフェースを通して行い、インストール先は adb のパスから割り出すため、現時点では MuMu 12 のみに対応しています。

## タスク

ゲームはホーム画面かフリーライブの選曲画面で止めておけば大丈夫です。「演奏アシスト」「統計ウィンドウを開く」「通知テスト」以外のタスクは、ゲームを開いていなくても先に起動し（すでに開いていればそのまま使い）、タイトル画面・ログインボーナス・お知らせを処理してゲームに入ります。

| タスク | 内容 |
|---|---|
| ゲーム起動 | ゲームが起動していなければ起動し、タイトル画面・ログインボーナス・お知らせを閉じてホーム画面に入ります。他のタスク（「演奏アシスト」「統計ウィンドウを開く」「通知テスト」を除く）は開始前に自分でこれを行うので、単独でチェックする必要はありません |
| アカウント切替 | 国際版のみ。現在の bilibili アカウントからログアウトし、ゲームのログイン履歴から入力したアカウントを選んでログインして（パスワード不要）、ホーム画面に入ります。すでにゲーム内にいるときは、先にゲームを再起動してタイトル画面に戻ります。アカウント名にはログイン履歴に表示される名前を入力します。一部だけでも構いませんが、1 つのアカウントにだけ一致するようにしてください。切り替えられるのはログイン履歴にあるアカウントだけなので、新しいアカウントは先にゲームで一度手動でログインしてください。複数のアカウントを交互にプレイするには、タスク一覧を「アカウント切替（A）→ 他のタスク → アカウント切替（B）→ 他のタスク」の順に並べます。アカウントセンター（Account Center）の「アカウント削除」や、ログイン履歴の各行右側にある ⓧ は押しません。演奏記録や「統計と実績」は、現時点ではアカウントを区別しません |
| 繰り返しプレイ | フリーライブで連続して演奏します。選曲方法（現在の曲 / ランダム / 未AP曲優先 / 指定した曲リスト）、難易度、プレイ回数、1 回あたりの LB 消費を選べます。難易度が「高難易度優先」のとき、「未AP曲優先」は EXPERT から EASY まで順に埋め、すべて終わったら EXPERT でランダムにプレイします。その他の選曲方法では EXPERT でプレイします |
| LB消化 | LIVE BOOST がなくなるまで連続して演奏します（毎回開始前に所持数を確認し、0 なら終了）。スターは使いません。プレイヤーランクが上がると LB が全回復するので、プレイ回数が見込みより多くなることがあります |
| 放置周回 | LB消化と同じく LB がなくなるまでプレイした後、バンド確認画面（Formation）で待機し、右上の回復カウントダウンを見ながら LB が 1 回あたりの消費数まで回復するのを待って、またプレイします（LB は 30 分ごとに 1 回復するので、消費 3 なら約 90 分に 1 回）。1 回あたりの消費を 0 にすると LB を待ちません：毎回開始前に所持数を確認し、LB があれば 1 消費し、なくなったら消費 0 に切り替えてプレイを続け、回復したらまた消費して、ずっと曲をプレイします。手動で止めるかプレイ回数に達するまで動き続けます。待機中に日付変更があると再ログインし、サーバーメンテナンスに当たったら 10 分ごとに確認して、メンテナンスが明けたら放置を再開します。オプション「定期回収」（デフォルトはオン、間隔 4 時間）：開始時にまずスタジオ練習（Studio Practice）を 1 回回収し、その後は設定した時間（1〜12）ごとに、プレイの合間や LB 待ちの間にホーム画面に戻ってもう一度回収し、終わったら放置に戻ります（スタジオ練習は最大 12 時間まで貯まり、超えると効率が 30% に下がります）。回収できなかったときは 30 分後にもう一度試します。オプション「毎日デイリー受け取り」（デフォルトはオン、22:30）：毎日設定した時刻（PC のローカル時刻）に、同じようにホーム画面に戻ってミッション、ミッションパス、期間限定ミッション、ビギナーミッション、T.G.W CARD、無料ガチャ、プレゼントボックスを 1 回受け取ります。受け取りきれなかったときは 10 分後にもう一度受け取ります（1 日最大 3 回）。タスク一覧の「デイリー受け取り」は放置の前に 1 回だけ実行されるので、放置中に日をまたいだ後はこのオプションで受け取ります。ゲームは毎日 23:00 に日付が変わるため、その日の分を受け取るには受け取り時刻を 23:00 より前にする必要があります。スターは使いません。このタスクは自分では終わらないので、タスク一覧の最後に置いてください |
| AP埋め | 選んだ難易度（EXPERT / HARD / NORMAL / EASY）でまだ ALL PERFECT していない曲を AP にします。選曲画面を一時的に「すべて」カテゴリに切り替え、「ALL PERFECT未達成」（NO ALL PERFECT）で絞り込みます。正常に終了したら元に戻します。「1 曲あたりの最大挑戦回数」打っても AP にならない曲はそれ以上打ちません。そのうち一度も最後まで打てなかった（同期失敗、ライフ 0）譜面は記録され、3 日間は AP埋めでも「未AP曲優先」でも打ちません（ゲームの更新で譜面が合わなくなったことが多いため、数日後に再試行します） |
| チャレンジライブ | 一部のイベント期間中のみ開催されます（開催していないときはエラーで終了）。ライブTOP（LIVE）から「チャレンジライブ」に入って連続して演奏し、毎回 LB ではなくチャレンジpt（CP）を消費して、CP が 1 回分に足りなくなるまでプレイします。保有数が選んだ消費量に足りないとゲームが OK を押させない（「チャレンジptが足りません。」と表示される）ため、そのときは「キャンセル」を押して停止します。OK を連打してタイムアウトすることはありません。オプション「1 回あたりのチャレンジpt消費」はデフォルトが 200（×1。最も節約でき、多く周回できます）で、400 / 800 / 1600（報酬 ×2 / ×4 / ×8）や、ゲーム内の設定を変えないことも選べます。1 回目の前に「CP設定」で選び、ラジオボタンを確認してから OK を押します。選曲方法「全曲を順番にプレイ」（デフォルト）は毎回一覧の次の曲に切り替え、最後まで行ったら最初の曲に戻ります。「未AP曲を優先」は毎回開始前に 1 曲ずつ、選んだ難易度が ALL PERFECT 済みかを確認し、未 AP の曲を先にプレイします（同じ曲は最大 3 回まで）。すべて AP 済みになったら順番にプレイします（難易度が「高難易度優先」のときは EXPERT → HARD → NORMAL → EASY の順に埋めます）。現在選択中の曲をプレイし続けることもできます。バンド確認画面の「スキップ」は押しません |
| 演奏アシスト | 演奏だけを代わりに行い、それ以外は自分で押します：曲を選んで LIVE START を押すと、ロード画面になった時点で同期を始め（他の演奏タスクと同じくロード中に基準を取ります）、演奏画面が出たら自動で演奏します。曲はバンド確認画面で認識するので、バンド確認画面を経由してください（認識できないとき、譜面サイトにない曲のときはその曲は演奏せず、理由をログに出します）。難易度は画面から読み、読めないときはレベルから判断します。フリーライブ・チャレンジライブ・協力ライブのいずれでも使えます（協力ライブでは難易度選択画面で曲を認識します。難易度はジャケット横の大きな文字、レベルはその枠の真上の数字です。難易度はこの画面で選ぶので、変えると認識をやり直します（大きな文字はまれに読めません。続けて数回読めなかったときは、変更前の難易度の譜面で演奏しないようその回は演奏しません）。「準備完了」を押した後、他のプレイヤーの準備とロードを最大 40 秒待ち、それより長いとその回は演奏しません。協力ライブは一時停止できず一時停止ボタンもないため、演奏画面の確認も演奏中のチェックも行わず、合っているかは同期結果だけで判断します）。LIVE CLEAR、リザルトのページ送り、ポップアップは自分で押すのを待ち、リザルト画面で ⇄ を 1 回押して FAST/SLOW を読むだけです。ほかのタスクと同じく成績を記録し、offset を補正します（判定数を読み終わる前に「次へ」を押すとその回は記録しません。判定数を読んだ後、FAST/SLOW を読む前に押すと判定数だけを記録します）。演奏中に一時停止してリトライを確定すると、その曲を最初からもう一度演奏します。「再開」だと途中からは合わせられないので、その回は演奏しません。同期できなかったときもその回は演奏しないので、自分で一時停止してリトライできます。ゲームの起動・再起動はせず、手動で止めるまで動き続けます |
| デイリー受け取り | スタジオ練習（回収）、ミッション、パスミッションと PASS の通常枠（パスが複数あるときは 1 つずつ受け取り）、期間限定ミッション、ビギナーミッション、T.G.W CARD、無料ガチャ、プレゼントボックスの報酬を順に受け取ります。項目ごとにオフにできます。押すのは点灯している「一括受け取り」（Claim All）と報酬ポップアップの OK だけです。T.G.W CARD ではデイリーポイント、デイリー報酬、ショップのカタログショップ（Catalog Shop）で価格が「無料」の商品を受け取り、スターが必要なものは押しません。無料ガチャ（デフォルトでオン）はホーム画面のガチャの入口に無料のバッジがあるときだけ行い、「無料」「1回」のボタンと、消費スター 0 個と書かれた確認ダイアログの OK だけを押します。演出は SKIP で飛ばし、結果画面ではガチャトップに戻るボタンだけを押します（「もう一度引く」、有償ガチャ、広告は押しません）。結果のスクリーンショットは `data/recruit/` に保存され MXU のログに表示されます。前後でスターの数も確認します（今のところ簡体字中国語の言語設定でのみ実機確認）。認識できないポップアップは押さず、エラーで停止します。デイリーミッションは曲をプレイしないと達成されないので、演奏タスクの後に置きます。オプション「ストーリー閲覧（スキップ）」（デフォルトはオフ）：未読のバンドストーリー、アナザーストーリー、絆ストーリー（Bond Story）を 1 話ずつスキップして読み終え、楽曲を解放し、読み終えた報酬を受け取ります。各話の初回はデータのダウンロードが必要です（ボイスなし、バンドストーリーで約 30MB）。オプション「イベントストーリー（スキップ）」（デフォルトはオフ）：期間限定イベント中、ライブTOP →「イベント」からイベントページに入り（イベントが複数あって先に「イベント選択」が出たときは開催中のものを押します）、「イベントストーリー」にある未読のイベントストーリー、アナザーストーリーを 1 話ずつスキップして読み終えます。期間限定イベントがないときはこの項目をスキップします |
| 統計ウィンドウを開く | 「統計と実績」ウィンドウを開き（下の「統計と実績」を参照。パッケージを替える前にウィンドウで記録を書き出せます。「バックアップと復元」を参照）、演奏記録をログに出力します（難易度ごとの AP した譜面、プレイしたがまだ AP していない譜面、直近 10 回）。エミュレーターは操作しません |
| 通知テスト | 全タスク共通のオプション「スマホに通知」でテストメッセージを 1 件送ります（下の「スマホに通知」を参照）。エミュレーターは操作しません |

### LB不足時にアイテムで補充

繰り返しプレイ、LB消化、放置周回、AP埋めにはオプション「LB不足時にアイテムで補充」（デフォルトはオフ）があります：毎回開始前に LB の所持数が 1 回あたりの消費数より少ないとき、「LB消費」→「回復」から入り、「アイテム」タブでのみブーストドリンク（Boost Drink）を使ってその回の分を補充します（先に小型の +1 を使い、足りなければ +10 を使います）。選んだ個数、回復のプレビュー、確認ポップアップの数字がすべて一致したときだけ OK を押します。「アイテム」タブでない場合や、一つでも一致しないところがある場合はキャンセルを押し、今回の実行ではそれ以上補充しません。スターは絶対に使わず、広告も見ません。

サブオプション「補充上限」は今回の実行で補充する LB の上限で、0 ならドリンクがなくなるまで補充します。ドリンクがなくなったら元の方法で続けます（LB消化はそこで終了し、放置周回は回復待ちを始めます）。1 回あたりの LB 消費を 1〜5 または「自動」に設定する必要があります。

### 1 回あたりの LB 消費：4、5 と「自動」

「1 回あたりの LB 消費」は 0〜5 から選べます（繰り返しプレイと AP埋めではゲーム内の設定を変更しないことも選べます）。4、5 は T.G.W CARD Lv.10、Lv.14 で解放されます。解放されていないときは「LB消費」ポップアップで選べる最大値にし、ログでお知らせします。

「自動（所持数で選ぶ）」にすると、毎回開始前に「LB消費」ポップアップを開き、そのときの所持数で選びます：

- 通常は選べる最大の消費数（4、5 が未解放なら 3）。所持数が足りなければ所持数を選び、残りをすべて消費します。
- 「全部消費」（1 回で最大 10 消費、4 以上持っているときだけ使えます。1 日に使える回数は月パスによります。たとえば最上位の月パスなら 1 日 5 回）は次の 2 つの場合に使います：LB を 10 以上持っているとき、または 1 回ずつ消費するより 2 回以上少なく済むとき（例：7 持っていて最大消費が 3 なら、1 回ずつだと 3 回、全部消費なら 1 回）。
- 「全部消費」は今日の回数を使い切るまで使います（ゲーム内で手動で使った分も含みます）：ポップアップに今日の回数を使い切った表示が出たとき、または今日使ったあとでチェックが入らなくなったときに `data/state.json` に記録し（「アカウント切替」で複数アカウントを回すときはアカウントごと）、その日（ゲームの日付。毎日 23:00 に変わります）はもう確認しません。
- LB消化で自動にすると LB がなくなったら終了します。放置周回で自動にすると、LB がなくなった後は 1 回復するたびに消費し、まとめて待ちません。放置周回で 0 にしたときはこれまでどおり「あれば 1 消費、なければ 0」です。

### スキップを使う

LB消化と放置周回にはオプション「スキップを使う」（デフォルトはオフ）があります：毎回の前にまずバンド確認画面の「スキップ」を押し、確認ポップアップで「1 回あたりの LB 消費」どおりに消費数を選んで（自動なら「全部消費」もここで使います）、選択中の曲をスキップします。その日のスキップ回数を使い切ったら演奏します。スキップはプレイ回数に数えず、終了時のログにスキップした回数を表示します。

- その回に LB を消費するときだけスキップします（1 回あたりの消費が 1〜5 か自動。放置周回で 0 のときは LB を持っているときだけスキップし、1 消費します）。LB がなくなったらスキップしません（確認ポップアップで所持 0 なら「閉じる」を押します）。その後はこれまでどおり続けます。
- チャレンジライブの「スキップ」は押しません。

### その他のオプション

- デフォルト以外のパラメータ（タイミングオフセットなど）を調整したいときは、[config.example.yaml](../../config.example.yaml) を展開先フォルダの `config.yaml` にコピーして編集してください。UI のオプションのほうが優先されます。
- 画面のログはデフォルトでは進捗と結果だけを表示します。全タスク共通のオプション「デバッグログ」をオンにすると、同期、譜面、タッチなどの詳細も表示されます。完全なログは常に `data/ournotes.log` に書き込まれます。
- 全タスク共通のオプション「アップデート確認」「自動アップデート」はデフォルトでオンです：タスク開始時（MFAA では UI を開いてエミュレーターに接続したときにも、前回タスクを実行したときの設定で一度）に GitHub で新しいリリースがあるか確認し、あればバックグラウンドでダウンロードします。進み具合と結果はタスク終了時のログでお知らせします。
  - 演奏部分だけの変更なら、タスクが動いていないときにそのまま切り替え、次のタスクから新しいバージョンになります。回数無制限の放置周回は曲の合間に少し止まって切り替え、終わったら自動で続けます。
  - UI が読む内容（タスク、オプション、UI の文言）が変わったときは UI の再起動が必要です：タスクが動いておらず UI が 2 分間操作されていなければ、UI を閉じて切り替え、もう一度開きます（タスクは自動で始めません）。UI を開くとすぐタスクを始める設定（MXU の「手動起動時も自動実行」、MFAA の「起動スクリプト」を含む起動方法）のときは再起動せず、UI を閉じたあとで切り替えます。
  - UI 本体、Python、依存ライブラリ、文字認識モデルが変わったときは圧縮ファイル全体をダウンロードして置き換えます。タイミングは同じです。`config/`、`data/`、`cache/`、`debug/` と UI 自身の設定はそのままです。
  - 置き換える前のファイルは `cache/update/backup/` にバックアップします。新しいバージョンが起動できなければ自動で元のバージョンに戻してログでお知らせし、そのバージョンへは自動アップデートしません。復元にも失敗した場合はバックアップを保持し、タスクと自動アップデートを停止します。ログに従って手動で復元するか、配布パッケージを新しいフォルダーに展開してから実行してください。
  - 「自動アップデート」をオフにすると新しいバージョンのお知らせだけになり、新しい圧縮ファイルは手動でダウンロードします。「自動アップデート」オプションのない古いバージョンは一度手動でダウンロードしてください。

### 統計と実績

累計稼働時間・演奏データ（日別のプレイ数、難易度ごと・譜面ごとの成績）・実績（いくつかは隠し実績）を 1 プレイごとに更新します。この機能が入る前の稼働時間は演奏記録から推定します。このツールでのプレイだけを集計します。ページは今のところ中国語のみです。見られる場所：

- 「統計と実績」ウィンドウ：タスク「統計ウィンドウを開く」を実行するか、パッケージフォルダーの「统计与成就」ショートカットをダブルクリックします（UI からいずれかのタスクを一度実行すると自動で作られます）。1 プレイごとに自動で更新され、実績を解除すると通知が出ます。実行中のタスクは概要の一番上に今していること（プレイ中の曲、次の LB が回復するまでの時間など）を表示し、数秒ごとに更新します。すでに開いているときは前面に出します。Edge のアプリモードで開きます（Edge がなければ Chrome、どちらもなければ既定のブラウザー）。
- MXU：「設定」ページの一番上にある「統計と実績」カード。設定を開き直すと更新されます。カード下部の「在浏览器里打开」（ブラウザーで開く）ボタンで、ウィンドウと同じページを既定のブラウザーで開けます（MXU 内蔵の Web サーバーが必要です。既定でオンです）。
- MFAA：タスク「統計ウィンドウを開く」の説明。別のタスクをクリックしてから戻ると更新されます。説明の最後にウィンドウを開くリンクがあります。

タスクが終わるとログに今回の稼働時間と累計を 1 行出力し、実績を解除すると「★」で始まる行を出力します。

### バックアップと復元

演奏記録・実行記録・実績・学習したオフセットはすべてパッケージの `data` フォルダーにあり、パッケージを消したり新しくダウンロードした完全版パッケージに替えたりすると一緒になくなります。替える前に「統計と実績」ウィンドウ右上の「备份与恢复」（バックアップと復元）から書き出しておいてください（MXU 設定ページのカードの「在浏览器里打开」で開いたページでは書き出し・インポートできません。ウィンドウで操作してください）：

- 「导出备份」（バックアップを書き出す）：保存先を選んで `OurNotes-Auto-backup-<日時>.zip` を 1 つ作ります。パッケージフォルダーの外（「ドキュメント」など）に置けば、古いパッケージを消しても残ります。
- 「导入」（インポート）：新しいパッケージで「統計と実績」ウィンドウを開き、「选择备份文件」（バックアップファイルを選ぶ）で書き出した zip を選びます。書き出していなくて古いパッケージが残っているときは、「没导出过？从旧的包目录导入」（書き出していない？古いパッケージフォルダーからインポート）を開き、古いパッケージのフォルダー（またはその `data` フォルダー）を入力して「读取」（読み込む）を押します。インポートされる件数を先に表示し、「确认导入」（インポートを確定）を押してからインポートします。終わるとページが自動で更新されます。
  - 上書きではなく統合です：このパッケージにある記録は 1 行も変えず、ないものだけ追加します。同じプレイ・同じ実行が重複することはありません。実績は早いほうの解除日時を残します。同じバックアップをもう一度インポートしても何も変わりません。
  - 学習したオフセットは、このパッケージがまだ学習していないときだけインポートします。全体のオフセットは PC とエミュレーターに依存するので、書き出したのと同じ PC でだけインポートします。譜面ごとのオフセットは別の PC でもインポートします。
  - 変更するファイルは先に `data/import_backup/<日時>` にコピーします（直近 5 回分）。結果がおかしいときはそこから戻せます。
  - プレイ系のタスクの実行中はインポートできません（演奏記録を同時に書くため）。先に停止してください。インポート中に始めたタスクは、インポートが終わるまで待ってから始まります。
  - 新しいバージョンで書き出したバックアップは、先にこのパッケージをそのバージョンに更新しないとインポートできないことがあります（そのときは案内が出ます）。
- ガチャのスクリーンショット（`data/recruit`）と `config.yaml` はバックアップに含まれないので、必要なら手動でコピーしてください。新しいパッケージでまだ一度もプレイしていなければ、古いパッケージの `data` フォルダーをまるごとコピーしても同じです。

### スマホに通知

全タスク共通のオプション「スマホに通知」で方式を選び「通知先」を入力すると、次のときにスマホへメッセージを送ります：

- プレイ系のタスク（繰り返しプレイ・LB消化・放置周回・AP埋め・チャレンジライブ）が終わったとき：何回プレイしたか、FC / AP / 失敗がそれぞれ何回か、かかった時間。デイリー受け取りが終わったときも 1 件送ります。
- タスクがエラーで終了したとき：何が起きたか（ログの最後のエラー）とかかった時間。演奏アシスト・ゲーム起動・アカウント切替はエラーのときだけ通知し（演奏アシストは手動で止めるまで動くので「完了」がありません）、統計ウィンドウを開くタスクは通知しません。
- 放置周回中にサーバーメンテナンスになったとき：待ち始めたときに 1 件、メンテナンスが明けて放置を再開したときにもう 1 件。

手動で停止したタスクは通知しません。「通知する内容」を「エラーとサーバーメンテナンスだけ」にすると、完了は通知しません。通知メッセージは今のところ中国語（簡体字）だけです。

| 方式 | 設定 |
|---|---|
| ntfy | 無料・登録不要。スマホに ntfy アプリ（Android、iOS）を入れ、他人に推測されないトピック名（英数字、- と _）を購読して、そのトピック名を「通知先」に入力します。自前の ntfy サーバーなら `https://ntfy.example.com/トピック名` のように完全な URL を入力します |
| Server酱（WeChat） | WeChat に通知します。[sct.ftqq.com](https://sct.ftqq.com/) に WeChat のスキャンでログインし、SendKey をコピーして「通知先」に入力します（Server酱³ の SendKey も使えます）。無料版は 1 日に送れる件数が限られるので、エラーとサーバーメンテナンスだけ通知するのもおすすめです |
| Bark（iPhone） | iPhone に通知します。App Store で Bark を入れて開き、表示される URL（`https://api.day.app/あなたのkey/` のようなもの。後ろに例のメッセージが付いた URL でも構いません）をコピーして「通知先」に入力します。key だけでも構いません。自前の Bark サーバーなら `https://サーバーのアドレス/あなたのkey` を入力します。エラーは即時通知で送るので、集中モード中でも通知されます |
| webhook | メッセージを JSON で「通知先」の URL に POST します：`event`（`done` / `error` / `maintenance` / `test`）、`title`、`text`、`time`（Unix 時刻）。自作のボットや他の通知サービスとの連携用です |

- 設定したら、タスク「通知テスト」（エミュレーターは操作しません）で届くか確認してください。届かないときはログに理由が出ます。
- 「通知先」はパスワードと同じです：知っている人は誰でもメッセージを送れますし、ntfy のトピックは他人も購読してメッセージを読めます。他人に教えないでください。ログにも記録しません。
- 送信に失敗したとき（ネットワークにつながらない、通知先の間違い、Server酱の 1 日の上限）は、ログに警告を出すだけでタスクはそのまま続きます。
- コマンドラインで使うときは `config.yaml` の `notify` で設定し（[config.example.yaml](../../config.example.yaml) を参照）、`ournotes-auto notify-test` で確認します。

## ゲーム内設定

| 設定 | 推奨 | 説明 |
|---|---|---|
| ノーツスピード | **5.00**（必須） | 同期パラメータ `play.sync.tau_s = 0.835` は 5.00 で測定したものです。毎回開始前にライブ前設定（Pre-LIVE Option Settings）のポップアップからスピードを読み取って確認しますが、一致しなくてもログで警告するだけで止まりません：他のスピードでも同期はできますが、押すタイミング全体がずれます。5.00 に戻すか、`calibrate motion` を実行して測り直してください（[人間らしさ](#人間らしさ任意デフォルトはオフ)の節にあるスピードの注意点も参照） |
| MV / 背景 | オフ、または暗めで動かない背景に変更（必須） | 開始時は画面が静止するのを待ってから最初のノーツを追跡します。背景が動き続けていると最大 4 秒待ったところで追跡を始め、明るい背景も混ざってしまうため、同期の失敗やずれの原因になります |
| 小節線表示（詳細 → ノーツ表示設定） | オン・オフどちらでも可 | 開始時に最初のノーツを追跡するとき、レーンを横切る小節線を認識して無視します。0.1.3 以前のバージョンは最初のノーツより先に落ちてくる小節線を最初のノーツと誤認し、その回全体が早くなってすぐにライフが 0 になるので、これらのバージョンを使う場合はオフにしてください |
| エフェクト・演出レベル | 必須ではないが、PC の性能が低い場合は下げることを推奨 | 画面を見るのは開始直後の数秒だけで（このときはまだタップエフェクトがありません）、カラフルなエフェクトは除外します。その後は譜面どおりに演奏し、右上のポーズボタンだけを見ます。ただし現時点では下げた設定でしかテストしておらず、高エフェクトでは明るい白の開幕エフェクトが追跡領域に混ざったり、全画面演出がポーズボタンを 2 秒以上隠し続けて演奏画面から離れたとみなされ、タッチが止まったりする可能性があります。下げるとエミュレーターのフレームレートも安定します |
| バンド確認画面の「LB消費」 | 設定項目 `game.lb_cost`（0〜5）または `game.lb_auto` で自動設定 | 1 回目の前に自動でポップアップを開いて選び、確認します。ゲームはこの設定を記憶します。0 なら LB を消費しません（LIVE START に「n ▸ n」と表示されます）。LB が足りないときはゲームが残りをすべて消費します。「LIVE BOOST回復」（アイテム / スター / 広告）が表示されたらキャンセルだけを押し、その回は 0 にします（`game.lb_refill` をオンにしているときは、先にアイテムのブーストドリンクで補充します。[上記](#lb不足時にアイテムで補充)を参照）。空欄（null）ならゲーム内の設定を変更しません |

PC やエミュレーターのインスタンスを変えたり、再インストールしたりした後は、まず低難易度で 1〜2 曲プレイし、ログに同期失敗やスピードの警告がないか確認してください。PC ごとにスクリーンショットやタッチの遅延は異なりますが、手動で調整する必要はありません：自動補正が 1 回ごとにタイミングオフセットを最大 1ms ずつ調整します（[タイミングオフセットと自動補正](#タイミングオフセットと自動補正)を参照）。

## タイミングオフセットと自動補正

`play.offset_ms` は全体のタイミングオフセットで、正の値は全体的に遅く押すことを意味し、スクリーンショット・入力・描画による遅延を補うためのものです。MuMu での実測では、約 -16ms で判定が中央に来ました。

毎回終了後、プログラムはリザルト画面の FAST/SLOW を読み取ります。FAST が多ければ遅らせ、SLOW が多ければ早めて、学習したオフセットを `data/state.json` に保存します（設定の `offset_ms` に加算されます）。次の場合は記録するだけで補正しません：実行が不安定なとき（遅れたバッチが多い）、または GOOD/BAD/MISS が多すぎるとき（たいていは間違ったノーツに同期しています）。

### 譜面ごとの補正

ずっと FAST 寄り、あるいは SLOW 寄りになる譜面があります（4 回以上プレイした 56 譜面のうち 22 譜面は平均のずれが大きめでした）。そのような譜面にグローバルなオフセットが引っ張られます。`play.auto_tune.per_chart`（デフォルトでオン）を有効にすると、ある譜面の直近 `chart_plays` 回（デフォルト 3）の偏りがグローバルの直近の傾向と逆向きで、平均の絶対値が `chart_threshold`（デフォルト 0.4）以上だった場合、そのずれはその譜面自身のものとして扱い、その譜面のオフセットだけを調整します（1 譜面あたり ±`chart_max_ms`、デフォルト ±10ms まで）。その回はグローバルオフセットを動かしません。譜面のオフセットはノーツスピードごとに別々に記録されるので、スピードを変えたら学び直しになります。

`ournotes-auto records` で確認すると、学習済みの譜面オフセットも（ずれの大きい順に）表示されます。`ournotes-auto records --clear-chart-offsets` ですべての譜面オフセットを消去でき（グローバルな学習値はそのまま）、ゲームの更新などで譜面が大きく変わったあとに一度消して学び直すとよいです。

## 人間らしさ（任意、デフォルトはオフ）

結果が整いすぎないようにします。UI では全タスク共通のオプションにあり、コマンドラインでは `--set` で変更します：

| 設定項目 | UI のオプション | 内容 |
|---|---|---|
| `play.touch.great_ratio` | ランダム GREAT（1% / 3% / 5%） | 判定総数に対してこの割合で、前後に他のノーツが近くにない通常のタップを選び、64〜69ms 早く／遅く押して GREAT にします（その回の同期誤差が大きいと、一部は PERFECT や GOOD になります。GOOD でもコンボは途切れません）。選曲方法が `ap` / `ap_first` のときは無効です。オンにすると、オフセットの自動補正では GREAT の FAST/SLOW を数えません |
| `play.touch.jitter_ms` | タイミングのゆらぎ（±8 / ±16ms） | 押す時刻が時間とともにゆっくりずれていき（最大 ± 設定値）、さらにジェスチャーごとに最大 ±3ms の独立したぶれが加わります。上限は 20ms |
| `play.touch.position_jitter` | タッチ位置ランダム | タッチ位置をノーツの幅の範囲でランダムに横へずらし、上下にも少し動かします。隣のタップ系ノーツの判定エリアには入りません（入ると押下がそのノーツに取られることがあります）。押さえているロングノーツも、同時に押さえている別のロングノーツの判定エリアには入りません。0〜1 の値が幅で、UI のスイッチをオンにすると 1 になります |

例：`ournotes-auto --set play.touch.great_ratio=0.03 --set play.touch.jitter_ms=8 --set play.touch.position_jitter=1 run`

「ランダム GREAT」をオンにしているときは、ゲーム内のノーツスピードをキャリブレーションした値（デフォルト 5.00）のままにしてください。GREAT の判定幅は ±83ms で、
わざと出す GREAT は 64〜69ms ずれた位置で押すため、全体のずれに使える余裕は十数ミリ秒しかありません。スピードがキャリブレーション時の値と違うと、
ずれが余裕を超えて、遅らせて押した GREAT が GOOD になることがあります（コンボは続きますが、結果は狙いどおりになりません）。
スピードが速いほど最初のノーツを追跡できる時間が短く（5.00 で約 1.8 秒、10.00 で約 0.45 秒）、1 回の中での同期誤差も平均化されにくくなるため、
この余裕は 10.00 で最も小さくなります。

## トラブル時の動作

- 演奏中に右上のポーズボタンが `play.guard_lost_s` 秒（デフォルト 2）続けて見えないと（一時停止、ポップアップ、演出で隠れた）、いったんタッチを止め、また見えたら再開します（演出で隠れていたので、この曲ではその後見えなくてもタッチを続けます）。`play.guard_abort_s` 秒（デフォルト 10）続けて見えないとその回を終了します：ゲームが一時停止中なら最初からリトライ（回数は `loop.sync_retries` に含む）、クラッシュなどはナビゲーションで画面を取り戻します。`guard_lost_s` を 0 にするとこのチェックをオフにします
- 最初のノーツの同期に失敗したときやライフが 0 になったときは、一時停止して「リトライ」を押し、その回をやり直します。LB は無駄になりません
- 画面がずっと認識できないときは 30 秒ごとにゲームのプロセスを確認し、ゲームがクラッシュしていれば adb で再起動して、タイトル画面から再ログインします。連続での再起動は最大 2 回までで、ホームに戻るとカウントがリセットされます
- 見たことのない、「OK」だけの通知ポップアップ（キャンセル、決定、購入、スターといった文字がないもの）はそのまま OK を押して続行し、ポップアップの文字をログに残して、スクリーンショットを `debug/nav` に保存します
- 右上に「スキップ」がある全画面演出（キャラクターの誕生日演出など）はスキップを押します。その後に続けて流れるストーリーは、右上のメニューを開いて SKIP を押してスキップします
- 最終手段：認識できない画面が 60 秒まったく変化しない、または動き続けているのに 150 秒認識できない（読み込み中・ダウンロード中は除く）ときは、ゲームを再起動して再ログインします。クラッシュ時と同じ再起動回数を共有し、回数を使い切ってもまだ止まっているときに停止します
- ゲームを十数時間続けて動かしていると次第に重くなり（60fps から 30 台に落ちる）、同期失敗や曲全体のずれが起きます。連続プレイ中、直近 5 回の同期で測ったフレームレート（中央値）が `loop.min_fps`（デフォルト 50、0 でチェックしない）を下回ると、曲を変える前にゲームを再起動します。再起動後も同じように低い（PC 自体の処理が追いつかない、エミュレーターがフレームレートを制限している）場合は、それを理由にした再起動はもう行いません。再起動後はゲームの画面の準備ができる（パッケージ名で画面の display が見つかる）まで待ってから続けるので、エミュレーターのホーム画面を撮ることはありません。画面のグローバル設定「重くなったらゲームを再起動」をオフにすると 0 にしたのと同じです
- サーバーメンテナンス（「サーバーメンテナンス中」の画面）：放置周回は 10 分ごとに「タイトルへ戻る」を押して再ログインし、メンテナンスが明けたら放置を再開します（「スマホに通知」をオンにしていれば、待ち始めたときと明けたときに通知します）。他のタスクはそのまま失敗します
- ゲームの更新：ログイン時の「データダウンロード」（追加のゲームデータ）は自動で OK を押してダウンロードします。「新しいバージョンを検出」（ストアでアプリ本体を更新する必要があるもの）は自動では押さず、タスクはそのまま失敗し、放置周回も止まります。自分でゲームを更新してから再開してください
- PC のメモリ不足：PC でまだコミットできるメモリ（タスクマネージャー「パフォーマンス › メモリ」の「コミット済み」）が 1 GB を切ると、ログで一度だけ知らせます。演奏プロセスがメモリを確保できずに終了したときは、PC のメモリ不足であることを画面に表示します。メモリを多く使っているプログラムを閉じるか PC を再起動してから始め直してください。タスクマネージャーの「詳細」タブを「コミット サイズ」で並べ替えると、どのプログラムが使っているかわかります

## 仕組み（概要）

1. **ナビゲーション**：スクリーンショット → OCR → 文字と位置から現在の画面を判断 → ボタンをタップ。ボタンはまず文字から正確に位置を特定し、見つからないときは固定座標を使います
2. **曲の識別**：バンド確認画面で曲名を OCR で読み取り、譜面サイトと国際版の多言語の曲名とあいまい一致させて musicId を得ます
3. **同期**：開始を押した後、画面が静止するのを待ち、最初のノーツがそのレーンの上方に現れたことを検出して、その先端を追跡します。ノーツが判定ラインに近づく動きは `y - y_h ∝ exp(t/τ)` に従うので、フィッティングして到達時刻を外挿し、そこから曲のゼロ点を求めます
4. **演奏**：譜面をタッチジェスチャー（タップ、フリック、ロング、トレース）に変換し、minitouch でタッチを注入（予備として MuMu IPC）、高精度タイマーで時間どおりに送ります。ゲームの判定表に従って、隣り合うノーツがタッチを互いに「取り合う」のを避けます：同時に横フリックする隣のノーツは開始点をずらし、後のタップに取られてしまう上フリック / トレースは早めに押します
5. **リザルト**：判定数と FAST/SLOW を読み取り、結果を記録してオフセットを補正します
