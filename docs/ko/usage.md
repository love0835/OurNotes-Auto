# 사용 설명서

[README](../../README.ko.md) 외의 자세한 설명입니다: 각 작업의 세부 사항, 게임 내 설정, 자동 보정, 사람처럼 치기, 문제가 생겼을 때의 처리, 실행 중 생성되는 파일과 작동 원리. 명령줄 사용법은 [명령줄](cli.md)을 참고하세요.

## 환경 요구 사항

- Windows, MuMu 에뮬레이터 12(이 프로젝트는 MuMu 6.6.x, Android 15 인스턴스에서 테스트했습니다)
- 에뮬레이터 해상도 **1280×720**(다른 16:9 해상도는 비율로 환산하지만 충분히 테스트하지 않았습니다. 16:9가 아니면 시작할 때 오류가 납니다), 프레임 레이트 60 이상(동기화 파라미터는 60프레임 스크린샷 기준으로 조정했습니다)
- 게임: 국제 서버(패키지명 `com.bilibili.sirius.official`, Google Play 버전은 `com.bilibili.sirius`이며 자동으로 인식합니다), 게임 언어는 简体中文, 繁體中文, English 또는 한국어. 또는 일본 서버(패키지명 `com.bushiroad.sirius`). 내비게이션은 OCR로 화면의 글자를 읽어서 하므로, 다른 서버에서는 버튼을 알아보지 못합니다. 한국어는 「게임 언어」를 한국어로 선택해야 합니다: 처음 실행할 때 한국어 문자 인식 모델(약 10 MB)을 자동으로 다운로드하고, 이후에는 매번 이 모델을 추가로 불러옵니다(두 모델로 함께 인식하므로 인식할 때마다 조금 느려집니다). 한국어를 선택하지 않으면 다운로드도 로드도 하지 않습니다
- 일본 서버: 「게임 언어」를 「日本語 (일본 서버)」로 선택하면 게임 시작 등의 작업이 일본 서버 클라이언트를 조작합니다(인식 모델을 추가로 다운로드하지 않습니다). 일본 서버 클라이언트는 Google Play에서 설치해야 하며, APK를 직접 설치하면 실행되지 않습니다. 계정 전환은 국제 서버에서만 쓸 수 있습니다. T.G.W CARD와 상점은 먼저 게임에서 직접 한 번 연령 확인을 해야 하며, 하지 않았으면 데일리 수령이 T.G.W CARD를 건너뜁니다. 일본 서버에서는 프리 라이브, AP 채우기, 데일리 수령만 검증했고 챌린지 라이브는 아직 시도하지 않았습니다
- 게임 내 설정은 [게임 내 설정](#게임-내-설정)을 참고하세요
- 채보 사이트 `assets.bdon.moe`와 곡명 API `haneoka.org`에 접속할 수 있어야 합니다(업데이트 확인과 자동 업데이트는 추가로 `github.com`에 접속하며, 끌 수 있습니다). 브라우저로는 열리는데 여기서 계속 다운로드에 실패하면(로그에 「다운로드 실패…현재 연결은 원격 호스트에 의해 강제로 끊겼습니다」) 전역 옵션 「네트워크 프록시」에 프록시 프로그램의 HTTP 포트(예: `127.0.0.1:7890`)를 입력하세요. 명령줄에서는 환경 변수 `HTTPS_PROXY`를 설정합니다
- 배포 패키지: 두 UI 모두 [VC++ 2015–2022 런타임](https://aka.ms/vs/17/release/vc_redist.x64.exe)이 필요합니다(MaaFramework 의존성). MFAA는 추가로 .NET 10 데스크톱 런타임이 필요하고(패키지의 `DependencySetup_依赖库安装_win.bat`으로 이것과 VC++ 런타임을 한 번에 설치할 수 있습니다), MXU는 WebView2가 필요합니다(Windows 10/11에는 보통 기본 포함). 패키지에는 Python 런타임, MaaFramework와 OCR 모델이 들어 있으며, 채보는 실행 중에 채보 사이트에서 다운로드합니다. 각 구성 요소의 라이선스는 [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md)를 참고하세요
- 소스에서 실행: Python ≥ 3.11, [명령줄](cli.md) 참고

## 에뮬레이터 연결

연결 설정에서 「MuMu 에뮬레이터」를 고르고, 사용할 에뮬레이터 인스턴스를 고릅니다. MuMu 12의 n번째 인스턴스의 adb 주소는 `127.0.0.1:16384+32n`입니다. 예를 들어 0번은 16384, 1번은 16416입니다. 스크린샷과 터치는 MuMu의 인터페이스를 거치고 설치 경로는 adb 경로에서 추정하므로, 현재는 MuMu 12만 지원합니다.

## 작업

게임이 홈 화면이나 프리 라이브 곡 선택 화면에 있으면 됩니다. 「연주 어시스트」, 「통계 창 열기」, 「알림 테스트」를 뺀 나머지 작업은 게임이 꺼져 있어도 먼저 실행하고(이미 켜져 있으면 그대로 사용) 타이틀 화면, 로그인 보너스, 공지사항을 처리해 게임에 들어갑니다.

| 작업 | 기능 |
|---|---|
| 게임 시작 | 게임이 실행 중이 아니면 실행하고, 타이틀 화면, 로그인 보너스, 공지사항을 넘겨 홈 화면에 들어갑니다. 「연주 어시스트」, 「통계 창 열기」, 「알림 테스트」를 뺀 나머지 작업은 처음에 이걸 하므로 따로 체크할 필요가 없습니다 |
| 계정 전환 | 국제 서버 전용. 현재 bilibili 계정에서 로그아웃하고, 게임의 로그인 기록에서 입력한 계정을 골라 로그인한 뒤(비밀번호 입력 불필요) 홈 화면에 들어갑니다. 이미 게임 중이면 먼저 게임을 재시작해 타이틀 화면으로 돌아갑니다. 계정 이름에는 로그인 기록에 표시되는 이름을 입력하며, 일부만 써도 되지만 한 계정에만 맞아야 합니다. 로그인 기록에 있는 계정으로만 전환할 수 있으므로, 새 계정은 먼저 게임에서 직접 한 번 로그인하세요. 여러 계정을 번갈아 플레이하려면 작업 목록을 「계정 전환(A) → 다른 작업 → 계정 전환(B) → 다른 작업」 순으로 배치하세요. 고객지원의 「注销」(계정 해지)와 로그인 기록 각 행 오른쪽의 ⓧ는 누르지 않습니다. 연주 기록과 통계 및 업적은 현재 계정별로 나누지 않습니다 |
| 반복 플레이 | 프리 라이브에서 연속으로 연주합니다. 선곡 방식(현재 곡 / 랜덤 / AP 미달성 우선 / 지정 곡 목록), 난이도, 플레이 횟수, 판당 LB 소모를 고를 수 있습니다. 난이도를 「고난이도 우선」으로 하면 「AP 미달성 우선」은 EXPERT부터 EASY까지 차례로 채우고, 모두 채우면 EXPERT로 랜덤 플레이합니다. 다른 선곡 방식은 EXPERT로 플레이합니다 |
| LB 소진 | LIVE BOOST를 다 쓸 때까지 연속으로 연주하며(매 판 전에 보유 수를 보고 0이면 종료), 스타는 쓰지 않습니다. 레벨 업하면 LB가 가득 회복되므로 판 수가 예상보다 많을 수 있습니다 |
| 방치 플레이 | LB 소진처럼 LB를 다 쓸 때까지 플레이한 뒤 밴드 확인 화면에서 멈추고, 오른쪽 위의 회복 카운트다운에 따라 LB가 판당 소모 수만큼 회복될 때까지 기다렸다가 다시 플레이합니다(LB는 30분마다 1개 회복되므로, 소모 3이면 약 90분에 한 판). 판당 소모를 0으로 하면 LB를 기다리지 않습니다: 매 판 전에 보유 수를 보고 LB가 있으면 1개 소모하고, 다 쓰면 소모 0으로 바꿔 계속하며, 회복되면 다시 소모해 쉬지 않고 플레이합니다. 직접 멈추거나 플레이 횟수를 채울 때까지 계속 실행됩니다. 기다리는 동안 날짜가 바뀌면 다시 로그인하고, 서버 점검 중이면 10분마다 확인하다가 서버가 열리면 방치 플레이를 이어 갑니다. 옵션 「정기 수령」(기본 켜짐, 간격 4시간): 시작할 때 스튜디오 연습을 먼저 한 번 수령하고, 이후 설정한 시간(1~12)마다 판과 판 사이나 LB를 기다리는 동안 홈 화면으로 돌아가 다시 수령하며, 끝나면 돌아와 방치 플레이를 계속합니다(스튜디오 연습은 최대 12시간까지 누적되며, 넘으면 효율이 30%로 떨어집니다). 수령에 실패하면 30분 뒤에 다시 수령합니다. 옵션 「매일 데일리 수령」(기본 켜짐, 22:30): 매일 설정한 시각(PC의 현지 시각)에 마찬가지로 홈 화면으로 돌아가 미션, 미션 패스, 기간 한정 미션, 초보자 미션, T.G.W CARD, 무료 뽑기, 선물함을 한 번 수령하며, 다 받지 못했으면 10분 뒤에 한 번 더 수령합니다(하루 최대 3번). 작업 목록의 「데일리 수령」은 방치 플레이 전에 한 번만 실행되므로, 방치 중 날짜가 바뀐 뒤에는 이 옵션으로 수령합니다. 게임은 매일 23:00에 날짜가 바뀌므로, 그날 몫을 받으려면 수령 시각이 23:00보다 빨라야 합니다. 스타는 쓰지 않습니다. 스스로 끝나지 않으므로 작업 목록의 마지막에 두세요 |
| AP 채우기 | 선택한 난이도(EXPERT / HARD / NORMAL / EASY)에서 아직 ALL PERFECT가 아닌 곡을 AP로 만듭니다. 곡 선택 화면을 잠시 「전체」 분류로 바꾸고 「ALL PERFECT 미달성」 필터를 걸며, 정상 종료하면 원래대로 되돌립니다. 「곡당 최대 시도」만큼 쳐도 AP가 안 된 곡은 더 치지 않습니다. 그중 한 번도 끝까지 치지 못한(동기화 실패, 라이프 0) 채보는 기록해 두고 3일 동안 AP 채우기와 「AP 미달성 곡 우선」 모두 치지 않습니다(게임 업데이트 뒤 채보가 맞지 않게 된 경우가 많아 며칠 뒤 다시 시도합니다) |
| 챌린지 라이브 | 일부 이벤트 기간에만 열립니다(열리지 않았으면 오류로 종료). 라이브 TOP에서 「챌린지 라이브」로 들어가 연속으로 연주하며, 판마다 LB 대신 챌린지 pt(CP)를 소모하고 CP가 한 판에 모자랄 때까지 플레이합니다. 보유량이 고른 소모량보다 적으면 게임이 OK를 눌러 주지 않으므로(「챌린지 pt가 부족합니다.」 표시) 이때는 「취소」를 눌러 멈춥니다. OK를 계속 눌러 시간 초과가 되지 않습니다. 옵션 「판당 챌린지 pt 소모」는 기본 200(×1. 가장 아낄 수 있어 여러 번 플레이할 수 있습니다)이며, 400 / 800 / 1600(보상 ×2 / ×4 / ×8)이나 게임 설정 그대로를 고를 수도 있습니다. 첫 판 전에 「챌린지 pt 소모 설정」에서 고르고 라디오 버튼을 확인한 뒤에야 「확인」을 누릅니다. 선곡 방식 「곡 순환」(기본)은 판마다 목록의 다음 곡으로 바꾸고, 끝에 닿으면 첫 곡으로 돌아갑니다. 「AP 미달성 곡 우선」은 매 판 시작 전 한 곡씩 선택한 난이도의 ALL PERFECT 여부를 확인해 AP를 못 한 곡부터 플레이하고(같은 곡은 최대 3번), 모두 AP면 순환 플레이합니다(난이도를 「고난이도 우선」으로 하면 EXPERT → HARD → NORMAL → EASY 순으로 채웁니다). 현재 선택된 곡을 계속 플레이할 수도 있습니다. 밴드 확인 화면의 「스킵」은 누르지 않습니다 |
| 연주 어시스트 | 연주만 대신하고 나머지는 직접 누릅니다. 곡을 고르고 LIVE START를 누르면, 로딩 화면이 나온 시점부터 동기화를 시작하고(다른 연주 작업과 마찬가지로 로딩 중에 기준을 잡습니다) 연주 화면이 나오면 자동으로 연주합니다. 곡은 밴드 확인 화면에서 인식하므로 밴드 확인 화면을 거쳐야 합니다(인식하지 못했거나 채보 사이트에 없는 곡이면 그 곡은 연주하지 않고 로그에 이유를 남깁니다). 난이도는 화면에서 읽고, 읽지 못하면 레벨로 판단합니다. 프리 라이브, 챌린지 라이브, 멀티 라이브 모두 됩니다(멀티 라이브는 난이도 선택 화면에서 곡을 인식합니다. 난이도는 아래 줄에서 난이도 색으로 칠해진 칸을 봅니다(선택된 칸은 다른 칸보다 채도가 약 2배 높아, 재킷 옆의 비스듬한 글자보다 훨씬 안정적으로 읽힙니다). 레벨은 그 칸 바로 위의 숫자입니다. 난이도는 바로 이 화면에서 고르므로 바꾸면 다시 인식합니다(연달아 몇 번 어느 칸도 두드러지지 않으면 바꾸기 전 난이도의 채보로 연주하지 않도록 그 판은 연주하지 않습니다). 「준비 완료」를 누른 뒤 다른 플레이어의 준비와 로딩을 최대 160초 기다립니다(남이 준비하는 시간은 내가 정할 수 없으므로 솔로의 40초보다 훨씬 깁니다. sync.multi_wait_s 참고). 그보다 오래 걸리면 그 판은 연주하지 않습니다. 멀티 라이브는 일시 정지가 없어 일시 정지 버튼도 없으므로 연주 화면 확인도, 연주 중 확인도 하지 않으며 맞게 연주 중인지는 동기화 결과로만 판단합니다). LIVE CLEAR, 결과 화면 넘기기, 팝업은 직접 누를 때까지 기다리며, 결과 화면에서 ⇄ 를 한 번 눌러 FAST/SLOW를 읽기만 합니다. 다른 작업처럼 성적을 기록하고 offset을 보정합니다(판정 수를 다 읽기 전에 「다음」을 누르면 그 판은 기록하지 않고, 판정 수를 읽은 뒤 FAST/SLOW를 읽기 전에 누르면 판정 수만 기록합니다). 연주 중 일시 정지 후 재시도를 확인하면 그 곡을 처음부터 다시 연주합니다. 「계속」을 누르면 중간부터는 맞출 수 없어 그 판은 연주하지 않습니다. 동기화에 실패한 판도 연주하지 않으니 직접 일시 정지 후 재시도할 수 있습니다. 게임을 실행하거나 재시작하지 않으며, 직접 멈출 때까지 계속 실행됩니다 |

### LB 부족 시 아이템으로 보충

반복 플레이, LB 소진, 방치 플레이, AP 채우기에는 모두 「LB 부족 시 아이템으로 보충」 옵션(기본 꺼짐)이 있습니다. 매 판 시작 전 보유 LB가 판당 소모 수보다 적으면 「LB 소모」 → 「회복」으로 들어가, 「아이템」 탭에서만 부스트 드링크로 이번 판에 필요한 만큼 채웁니다(먼저 미니 +1을 쓰고, 모자라면 +10을 씁니다). 선택한 수량, 회복 미리 보기, 확인 팝업의 숫자가 모두 맞을 때만 「확인」을 누르며, 「아이템」 탭이 아니거나 하나라도 맞지 않으면 「취소」를 누르고 이번 실행에서는 더 보충하지 않습니다. 스타는 절대 쓰지 않고 광고도 보지 않습니다.

하위 옵션 「최대 보충량」은 이번 실행에서 최대로 보충할 LB 수이며, 0은 드링크를 다 쓸 때까지입니다. 드링크를 다 쓰면 원래 방식대로 계속합니다(LB 소진은 그대로 종료하고, 방치 플레이는 회복을 기다리기 시작합니다). 판당 소모 LB를 1~5 또는 「자동」으로 설정해야 합니다.

### 판당 LB 소모: 4, 5와 「자동」

「판당 LB 소모」는 0~5 중에서 고를 수 있습니다(반복 플레이와 AP 채우기에서는 게임 설정을 그대로 두는 것도 가능). 4, 5는 T.G.W CARD 10레벨, 14레벨에서 해금됩니다. 해금되지 않았으면 「LB 소모」 팝업에서 고를 수 있는 최댓값으로 하고 로그에 알립니다.

「자동(보유량에 맞춰 선택)」으로 하면 매 판 시작 전에 「LB 소모」 팝업을 열어 그때의 보유량으로 고릅니다:

- 보통은 고를 수 있는 최대 소모량(4, 5가 해금되지 않았으면 3). 보유량이 부족하면 보유량을 골라 남은 LB를 모두 소모합니다.
- 「전부 소모」(한 판에 최대 10개 소모, 4개 이상 보유할 때만 사용 가능. 하루에 쓸 수 있는 횟수는 월정액에 따라 다르며, 예를 들어 최상위 월정액은 하루 5회)는 두 경우에 사용합니다: LB를 10개 이상 가졌을 때, 또는 한 판씩 소모할 때보다 2판 이상 줄일 수 있을 때(예: 7개 보유, 최대 소모 3이면 한 판씩은 3판, 전부 소모는 1판).
- 「전부 소모」는 오늘 횟수를 다 쓸 때까지 사용합니다(게임에서 직접 쓴 횟수도 포함): 팝업에 오늘 횟수를 다 썼다고 표시되거나, 오늘 사용한 뒤 체크가 되지 않으면 `data/state.json`에 기록하고(「계정 전환」으로 여러 계정을 돌릴 때는 계정별로) 그날(게임 날짜, 매일 23:00에 바뀜)은 다시 확인하지 않습니다.
- LB 소진을 자동으로 하면 LB를 다 쓰면 끝납니다. 방치 플레이를 자동으로 하면 LB를 다 쓴 뒤 1개 회복될 때마다 소모하며 모아서 기다리지 않습니다. 방치 플레이를 0으로 하면 지금처럼 「있으면 1개 소모, 없으면 0」입니다.

### 스킵 사용

LB 소진과 방치 플레이에는 옵션 「스킵 사용」(기본 꺼짐)이 있습니다: 매 판 전에 먼저 밴드 확인 화면의 「스킵」을 누르고, 확인 팝업에서 「판당 LB 소모」대로 소모량을 골라(자동이면 「전부 소모」도 여기서 사용) 지금 선택된 곡을 스킵합니다. 그날의 스킵 횟수를 다 쓰면 연주합니다. 스킵은 플레이 횟수에 세지 않으며, 끝날 때 로그에 스킵한 횟수를 표시합니다.

- 그 판에서 LB를 소모할 때만 스킵합니다(판당 소모 1~5 또는 자동. 방치 플레이를 0으로 하면 LB가 있을 때만 스킵하고 1개 소모). LB를 다 쓰면 스킵하지 않고(확인 팝업에서 보유 0이면 「닫기」를 누름) 원래 방식대로 계속합니다.
- 챌린지 라이브의 「스킵」은 누르지 않습니다.

### 기타 옵션

- 기본값 외의 파라미터(시간 오프셋 등)를 조정해야 하면 [config.example.yaml](../../config.example.yaml)을 압축을 푼 폴더에 `config.yaml`로 복사해 수정하세요. UI의 옵션이 이 파일보다 우선합니다.
- UI 로그에는 기본적으로 진행 상황과 결과만 표시됩니다. 전역 옵션 「디버그 로그」를 켜면 동기화, 채보, 터치 등의 세부 정보도 표시됩니다. 전체 로그는 항상 `data/ournotes.log`에 기록됩니다.
- 전역 옵션 「업데이트 확인」「자동 업데이트」는 기본으로 켜져 있습니다: 작업을 시작할 때(MFAA는 UI를 열고 에뮬레이터에 연결될 때도 지난번 작업 실행 때의 설정으로 한 번) GitHub에 새로 출시된 버전이 있는지 확인하고, 있으면 백그라운드에서 내려받습니다. 진행 상황과 결과는 작업이 끝날 때 로그에 알려 줍니다.
  - 연주 부분만 바뀌었으면 실행 중인 작업이 없을 때 바로 교체하고, 다음 작업부터 새 버전을 씁니다. 횟수 제한 없는 방치 플레이는 곡 사이에 잠깐 멈춰 교체한 뒤 자동으로 이어 갑니다.
  - UI가 읽는 내용(작업, 옵션, UI 문구)이 바뀌었으면 UI를 다시 시작해야 합니다: 실행 중인 작업이 없고 UI가 2분 동안 쓰이지 않으면 UI를 닫고 교체한 뒤 다시 엽니다(작업을 자동으로 시작하지는 않습니다). UI를 열자마자 작업을 시작하도록 설정되어 있으면(MXU의 「수동 실행 시에도 자동 실행」, MFAA에서 「启动脚本(시작 스크립트)」이 들어간 시작 방식) 대신 다시 시작하지 않고, UI를 닫은 뒤 교체합니다.
  - UI 프로그램, Python, 의존 라이브러리, 문자 인식 모델이 바뀌었으면 압축 파일 전체를 내려받아 교체합니다. 시점은 위와 같습니다. `config/`, `data/`, `cache/`, `debug/`와 UI 자체 설정은 건드리지 않습니다.
  - 교체하기 전 파일은 `cache/update/backup/`에 백업합니다. 새 버전이 시작되지 않으면 원래 버전으로 자동 복원하고 로그에 알려 주며, 그 버전으로는 다시 자동 업데이트하지 않습니다. 복원도 실패하면 백업을 보존하고 작업과 자동 업데이트를 중지합니다. 로그에 따라 수동으로 복원하거나 릴리스 패키지를 새 폴더에 압축 해제한 뒤 실행하세요.
  - 「자동 업데이트」를 끄면 새 버전 알림만 하므로 새 압축 파일을 직접 다운로드해야 합니다. 「자동 업데이트」 옵션이 없는 이전 버전은 한 번 직접 다운로드해야 합니다.

### 통계 및 업적

누적 실행 시간, 연주 데이터(일별 판수, 난이도별·채보별 전적), 업적(몇 개는 숨겨져 있음)을 매 판마다 갱신합니다. 이 기능이 들어오기 전의 실행 시간은 연주 기록으로 추정합니다. 이 도구로 친 판만 집계하며, 페이지는 현재 중국어만 지원합니다. 보는 곳:

- 「통계 및 업적」 창: 작업 「통계 창 열기」를 실행하거나, 패키지 폴더의 「统计与成就」 바로 가기를 더블클릭합니다(UI에서 아무 작업이나 한 번 실행하면 자동으로 만들어집니다). 매 판마다 자동으로 새로 고쳐지고, 업적을 해제하면 알림이 뜹니다. 실행 중인 작업은 개요 맨 위에 지금 하고 있는 일(플레이 중인 곡, 다음 LB가 회복될 때까지 남은 시간 등)을 보여 주며 몇 초마다 갱신됩니다. 이미 열려 있으면 앞으로 가져옵니다. Edge의 앱 모드로 엽니다(Edge가 없으면 Chrome, 둘 다 없으면 기본 브라우저).
- MXU: 「설정」 페이지 맨 위의 「통계 및 업적」 카드. 설정을 다시 열면 새로 고쳐집니다. 카드 아래쪽의 「在浏览器里打开」(브라우저에서 열기) 버튼을 누르면 창과 같은 페이지를 기본 브라우저로 엽니다(MXU 내장 웹 서버가 켜져 있어야 하며, 기본으로 켜져 있습니다).
- MFAA: 작업 「통계 창 열기」의 설명. 다른 작업을 눌렀다가 돌아오면 새로 고쳐집니다. 설명 끝에 창을 여는 링크가 있습니다.

작업이 끝나면 로그에 이번 실행 시간과 누적 데이터를 한 줄로 표시하고, 업적을 해제하면 「★」로 시작하는 줄을 표시합니다.

### 백업 및 복원

연주 기록, 실행 기록, 업적, 학습한 오프셋은 모두 패키지의 `data` 폴더에 있어서, 패키지를 지우거나 새로 내려받은 전체 패키지로 바꾸면 함께 사라집니다. 바꾸기 전에 「통계 및 업적」 창 오른쪽 위의 「备份与恢复」(백업 및 복원)에서 내보내 두세요(MXU 설정 페이지 카드의 「在浏览器里打开」으로 연 페이지에서는 내보내기와 가져오기를 할 수 없으니 창에서 하세요):

- 「导出备份」(백업 내보내기): 저장할 곳을 골라 `OurNotes-Auto-backup-<시각>.zip` 파일 하나를 만듭니다. 패키지 폴더 밖(「문서」 등)에 두면 예전 패키지를 지워도 남습니다.
- 「导入」(가져오기): 새 패키지에서 「통계 및 업적」 창을 열고 「选择备份文件」(백업 파일 선택)으로 내보낸 zip을 고릅니다. 내보낸 적이 없고 예전 패키지가 남아 있으면 「没导出过？从旧的包目录导入」(내보낸 적 없음? 예전 패키지 폴더에서 가져오기)를 펼쳐 예전 패키지 폴더(또는 그 `data` 폴더)를 입력하고 「读取」(읽기)를 누릅니다. 먼저 얼마나 가져올지 보여 주고, 「确认导入」(가져오기 확인)를 눌러야 가져옵니다. 끝나면 페이지가 자동으로 새로 고쳐집니다.
  - 덮어쓰지 않고 합칩니다. 이 패키지에 있는 기록은 한 줄도 바꾸지 않고 없는 것만 추가하며, 같은 판이나 같은 실행이 중복되지 않습니다. 업적은 더 이른 해제 시각을 남깁니다. 같은 백업을 다시 가져와도 아무것도 바뀌지 않습니다.
  - 학습한 오프셋은 이 패키지가 아직 학습하지 않았을 때만 가져옵니다. 전역 오프셋은 PC와 에뮬레이터에 따라 달라서 내보낸 PC와 같은 PC에서만 가져오고, 채보별 오프셋은 다른 PC에서도 가져옵니다.
  - 바뀌는 파일은 먼저 `data/import_backup/<시각>`에 복사합니다(최근 5번 보관). 결과가 이상하면 거기서 되돌릴 수 있습니다.
  - 플레이 작업이 실행 중일 때는 가져올 수 없습니다(연주 기록을 같이 쓰기 때문). 먼저 멈추세요. 가져오는 동안 시작한 작업은 가져오기가 끝날 때까지 기다렸다가 시작합니다.
  - 새 버전에서 내보낸 백업은 이 패키지를 먼저 그 버전으로 업데이트해야 가져올 수 있을 수 있습니다(그때는 안내가 나옵니다).
- 뽑기 스크린샷(`data/recruit`)과 `config.yaml`은 백업에 포함되지 않으니 필요하면 직접 복사하세요. 새 패키지에서 아직 한 판도 치지 않았다면 예전 패키지의 `data` 폴더를 통째로 복사해도 됩니다.

### 휴대폰 알림

전역 옵션 「휴대폰 알림」에서 방식을 고르고 「알림 주소」를 입력하면 다음과 같을 때 휴대폰으로 메시지를 보냅니다:

- 플레이 작업(반복 플레이, LB 소진, 방치 플레이, AP 채우기, 챌린지 라이브)이 끝났을 때: 몇 판 쳤는지, FC / AP / 실패가 각각 몇 판인지, 걸린 시간. 데일리 수령이 끝났을 때도 하나 보냅니다.
- 작업이 오류로 끝났을 때: 무슨 오류인지(로그의 마지막 오류)와 걸린 시간. 연주 어시스트, 게임 시작, 계정 전환은 오류일 때만 알리고(연주 어시스트는 직접 멈출 때까지 실행되므로 「완료」가 없습니다), 통계 창 열기는 알리지 않습니다.
- 방치 플레이 중 서버 점검을 만났을 때: 기다리기 시작할 때 한 번, 서버가 열려 방치 플레이를 이어 갈 때 한 번 더.

직접 중지한 작업은 알리지 않습니다. 「알릴 내용」을 「오류와 서버 점검만」으로 하면 완료는 알리지 않습니다. 알림 메시지는 지금은 중국어(간체)로만 나옵니다.

| 방식 | 설정 |
|---|---|
| ntfy | 무료, 가입 불필요. 휴대폰에 ntfy 앱(Android, iOS)을 설치하고 남이 추측할 수 없는 토픽 이름(영문, 숫자, -와 _)을 구독한 뒤 그 이름을 「알림 주소」에 입력하세요. 직접 운영하는 ntfy 서버면 `https://ntfy.example.com/토픽이름`처럼 전체 URL을 입력합니다 |
| Server酱(WeChat) | WeChat으로 보냅니다. [sct.ftqq.com](https://sct.ftqq.com/)에 WeChat 스캔으로 로그인해 SendKey를 복사하고 「알림 주소」에 입력하세요(Server酱³의 SendKey도 됩니다). 무료 버전은 하루에 보낼 수 있는 개수가 정해져 있으니 오류와 서버 점검만 알리는 것도 좋습니다 |
| Bark(iPhone) | iPhone으로 보냅니다. App Store에서 Bark를 설치해 열고, 표시되는 URL(`https://api.day.app/내key/` 같은 것. 뒤에 예시 메시지가 붙은 URL도 됩니다)을 복사해 「알림 주소」에 입력하세요. key만 입력해도 됩니다. 직접 운영하는 Bark 서버면 `https://서버주소/내key`를 입력합니다. 오류는 시간 민감 알림으로 보내므로 집중 모드 중에도 알립니다 |
| webhook | 메시지를 JSON으로 「알림 주소」의 URL에 POST합니다: `event`(`done` / `error` / `maintenance` / `test`), `title`, `text`, `time`(Unix 시각). 직접 만든 봇이나 다른 알림 서비스와 연결할 때 씁니다 |

- 설정한 뒤 작업 「알림 테스트」(에뮬레이터는 조작하지 않음)로 잘 오는지 확인하세요. 오지 않으면 로그에 이유가 나옵니다.
- 「알림 주소」는 비밀번호와 같습니다. 아는 사람은 누구나 메시지를 보낼 수 있고, ntfy 토픽은 다른 사람도 구독해 메시지를 볼 수 있습니다. 다른 사람에게 알려 주지 마세요. 로그에도 남기지 않습니다.
- 보내기에 실패하면(네트워크 연결 안 됨, 주소 오류, Server酱 하루 한도 초과) 로그에 경고를 남길 뿐 작업은 그대로 계속됩니다.
- 명령줄에서 쓸 때는 `config.yaml`의 `notify`에서 설정하고([config.example.yaml](../../config.example.yaml) 참고) `ournotes-auto notify-test`로 확인합니다.

## 게임 내 설정

| 설정 | 권장 | 설명 |
|---|---|---|
| 노트 속도 | **5.00**(필수) | 동기화 파라미터 `play.sync.tau_s = 0.835`는 5.00에서 측정했습니다. 매 판 시작 전 라이브 전 설정 팝업에서 속도를 읽어 확인하며, 다르면 로그에 경고만 하고 멈추지는 않습니다: 다른 속도에서도 동기화는 되지만 누르는 타이밍이 전체적으로 어긋납니다. 5.00으로 되돌리거나 `calibrate motion`을 실행해 다시 측정하세요(속도 요구 사항은 [사람처럼 치기](#사람처럼-치기-선택-사항-기본값-꺼짐) 절도 참고) |
| MV / 배경 | 끄거나, 어둡고 움직이지 않는 배경으로 변경(필수) | 시작할 때 화면이 멈추기를 기다린 뒤 첫 노트를 추적합니다. 배경이 계속 움직이면 최대 4초만 기다리고 추적을 시작하며, 밝은 배경은 추적에 섞여 들어와 동기화가 실패하거나 부정확해집니다 |
| 마디선 표시(상세 → 노트 설정) | 켜든 끄든 상관없음 | 시작할 때 첫 노트를 추적하면서 레인을 가로지르는 마디선을 알아보고 건너뜁니다. 0.1.3 이하 버전은 첫 노트보다 먼저 내려오는 마디선을 첫 노트로 착각해 판 전체가 빨라지고 금방 라이프가 0이 되므로, 이 버전들을 쓸 때는 꺼 두세요 |
| 이펙트, 연출 레벨 | 필수는 아니지만, PC 사양이 낮으면 낮추기를 권장 | 시작 후 몇 초만 화면을 보며(이때는 아직 타격 이펙트가 없습니다) 컬러 이펙트는 걸러 냅니다. 이후에는 채보대로 연주하면서 오른쪽 위의 일시정지 버튼만 봅니다. 다만 지금까지는 낮춘 설정에서만 테스트했으며, 이펙트가 높으면 밝은 흰색 시작 이펙트가 추적 영역에 섞여 들거나, 전체 화면 연출이 일시정지 버튼을 2초 넘게 계속 가려서 연주 화면을 벗어난 것으로 판단해 터치를 멈출 수 있습니다. 낮추면 에뮬레이터 프레임 레이트도 더 안정됩니다 |
| 밴드 확인 화면의 「LB 소모」 | 설정 항목 `game.lb_cost`(0~5) 또는 `game.lb_auto`로 자동 설정 | 첫 판 전에 자동으로 팝업을 열어 고르고 확인하며, 게임이 이 값을 기억합니다. 0은 LB를 소모하지 않습니다(LIVE START에 「n ▸ n」으로 표시). LB가 부족하면 게임이 남은 LB를 모두 소모합니다. 「라이브 부스트 회복」(아이템/스타/광고)이 뜨면 「취소」만 누르고 그 판은 0으로 바꿉니다(`game.lb_refill`을 켜면 먼저 아이템의 부스트 드링크로 보충합니다. [위](#lb-부족-시-아이템으로-보충) 참고). 비워 두면(null) 게임 설정을 바꾸지 않습니다 |

PC나 에뮬레이터 인스턴스를 바꾸거나 다시 설치한 뒤에는 먼저 낮은 난이도로 한두 곡을 플레이하고, 로그에 동기화 실패나 속도 경고가 없는지 확인하세요. PC마다 스크린샷과 터치 지연이 다르지만 직접 조정할 필요는 없습니다: 자동 보정이 판마다 시간 오프셋을 조정하며, 한 판에 최대 1ms씩 바꿉니다([시간 오프셋과 자동 보정](#시간-오프셋과-자동-보정) 참고).

## 시간 오프셋과 자동 보정

`play.offset_ms`는 전역 시간 오프셋으로, 양수이면 전체적으로 더 늦게 누릅니다. 스크린샷, 입력, 렌더링으로 생기는 지연을 보정하는 데 씁니다. MuMu에서는 약 -16ms일 때 판정이 가운데에 왔습니다.

매 판이 끝나면 프로그램이 결과 화면의 FAST/SLOW를 읽습니다. FAST가 많으면 뒤로 밀고, SLOW가 많으면 앞으로 당기며, 학습한 오프셋을 `data/state.json`에 저장합니다(설정의 `offset_ms`에 더해집니다). 다음 경우에는 기록만 하고 보정하지 않습니다: 실행이 불안정할 때(늦게 보낸 배치가 많음), 또는 GOOD/BAD/MISS가 너무 많을 때(대개 잘못된 노트에 동기화된 경우).

### 채보별 보정

계속 FAST 쪽이나 SLOW 쪽으로 치우치는 채보가 있습니다(4판 이상 플레이한 56개 채보 중 22개의 평균 편차가 컸습니다). 이런 채보가 전역 오프셋을 앞뒤로 끌어당깁니다. `play.auto_tune.per_chart`(기본 켜짐)를 켜면, 어떤 채보의 최근 `chart_plays`판(기본 3) 편차 방향이 전역 최근 흐름과 반대이고 평균 절댓값이 `chart_threshold`(기본 0.4) 이상일 때 그 편차를 그 채보 자신의 것으로 보고 그 채보의 오프셋만 조정합니다(채보당 ±`chart_max_ms`, 기본 ±10ms). 그 판에는 전역 오프셋을 건드리지 않습니다. 채보 오프셋은 노트 속도별로 따로 기록되므로 속도를 바꾸면 다시 배워야 합니다.

`ournotes-auto records`로 보면 배워 둔 채보 오프셋도 함께 나옵니다(편차가 큰 순서). `ournotes-auto records --clear-chart-offsets`는 모든 채보 오프셋을 지웁니다(전역 학습값은 그대로). 게임 업데이트처럼 채보가 크게 바뀐 뒤에 한 번 지우고 다시 배우면 됩니다.

## 사람처럼 치기 (선택 사항, 기본값 꺼짐)

결과가 너무 깔끔하지 않게 만듭니다. UI에서는 전역 옵션에 있고, 명령줄에서는 `--set`으로 바꿉니다:

| 설정 항목 | UI 옵션 | 기능 |
|---|---|---|
| `play.touch.great_ratio` | 랜덤 GREAT(1% / 3% / 5%) | 판정 총수에 대한 이 비율만큼, 앞뒤에 바로 붙은 다른 노트가 없는 일반 탭을 골라 64~69ms 일찍 또는 늦게 눌러 GREAT로 만듭니다(한 판의 동기화 오차가 크면 그중 일부는 PERFECT나 GOOD이 되며, GOOD은 콤보가 끊기지 않습니다). 선곡 방식이 `ap` / `ap_first`이면 적용되지 않습니다. 켜면 자동 보정할 때 GREAT의 FAST/SLOW는 세지 않습니다 |
| `play.touch.jitter_ms` | 타이밍 흔들림(±8 / ±16ms) | 누르는 시각이 시간에 따라 천천히 흘러가고(최대 ± 설정값), 제스처마다 최대 ±3ms의 독립적인 떨림이 더해집니다. 상한은 20ms입니다 |
| `play.touch.position_jitter` | 터치 위치 랜덤 | 터치 지점을 노트 너비 안에서 랜덤하게 가로로 옮기고, 위아래로도 조금 움직입니다. 옆에 있는 탭 계열 노트의 판정 영역으로는 옮기지 않으며(그러지 않으면 누른 터치를 그 노트가 가져갈 수 있습니다), 누르고 있는 롱 노트도 동시에 누르고 있는 다른 롱 노트의 판정 영역으로 옮기지 않습니다. 값 0~1은 폭이며, UI 스위치를 켜면 1입니다 |

예: `ournotes-auto --set play.touch.great_ratio=0.03 --set play.touch.jitter_ms=8 --set play.touch.position_jitter=1 run`

「랜덤 GREAT」를 켰다면 게임 내 노트 속도를 보정에 사용한 값(기본 5.00)으로 유지하세요. GREAT의 판정 범위는 ±83ms이고,
일부러 친 GREAT는 64~69ms 어긋난 곳에 떨어지므로 전체 오프셋에 남는 여유는 십몇 밀리초뿐입니다. 속도가 보정할 때 쓴 값이 아니면
오프셋이 이 범위를 넘어 늦게 친 GREAT가 GOOD이 될 수 있습니다(콤보는 유지되지만 결과가 달라집니다).
속도가 빠를수록 첫 노트의 추적 시간이 짧아지고(5.00은 약 1.8초, 10.00은 약 0.45초), 한 판 안의 동기화 오차도 평균으로 상쇄되기 어려워지므로,
이 여유는 10.00에서 가장 빠듯합니다.

## 예외 상황

- 연주 중 `play.guard_lost_s`초(기본 2) 동안 계속 오른쪽 위의 일시정지 버튼이 보이지 않으면(일시정지, 팝업, 연출 효과에 가려짐) 일단 터치를 멈추고, 다시 보이면 이어서 칩니다(연출에 가려진 것이므로 이 곡에서는 이후 보이지 않아도 계속 터치합니다). `play.guard_abort_s`초(기본 10) 동안 계속 보이지 않으면 그 판을 끝냅니다: 게임이 일시정지 상태면 처음부터 재시도(횟수는 `loop.sync_retries`에 포함)하고, 강제 종료 등은 내비게이션이 화면을 다시 찾습니다. `guard_lost_s`를 0으로 설정하면 이 검사를 끕니다
- 첫 노트 동기화에 실패하거나 라이프가 0이 되면 일시정지한 뒤 「재시도」를 눌러 그 판을 다시 시작하므로, LB를 낭비하지 않습니다
- 화면을 계속 알아보지 못하면 30초마다 게임 프로세스를 확인합니다. 게임이 강제 종료되었으면 adb로 다시 실행하고, 타이틀 화면에서 다시 로그인합니다. 연속 재시작은 최대 2번이며, 홈으로 돌아오면 다시 셉니다
- 처음 보는, 「확인」 버튼 하나만 있는 알림 팝업(취소, 구매, 스타 같은 글자가 없는 것)은 바로 「확인」을 눌러 계속하며, 팝업의 글자를 로그에 남기고 스크린샷을 `debug/nav`에 저장합니다
- 오른쪽 위에 「스킵」이 있는 전체 화면 연출(예: 캐릭터 생일 연출)은 스킵을 누르고, 이어서 재생되는 스토리는 오른쪽 위 메뉴를 열어 SKIP으로 건너뜁니다
- 안전장치: 알아볼 수 없는 화면이 60초 동안 전혀 변하지 않거나, 계속 움직이지만 150초 동안 알아보지 못하면(로딩, 다운로드 중은 제외) 게임을 재시작해 다시 로그인합니다. 위의 강제 종료 때와 재시작 횟수를 공유하며, 재시작 횟수를 다 쓰고도 멈춰 있으면 그때 중지합니다
- 게임을 십몇 시간 연속으로 실행하면 점점 버벅여서(60fps에서 30대로 떨어짐) 동기화에 실패하고 곡 전체가 어긋납니다. 연속으로 플레이하는 동안 최근 5번의 동기화에서 측정한 프레임 레이트(중앙값)가 `loop.min_fps`(기본 50, 0은 검사 안 함)보다 낮으면 곡을 바꾸기 전에 게임을 재시작합니다. 재시작한 뒤에도 여전히 낮으면(PC 자체가 감당하지 못하거나 에뮬레이터가 프레임 레이트를 제한한 경우) 이 이유로는 더 재시작하지 않습니다. 재시작한 뒤에는 게임 화면이 준비될 때까지(패키지 이름으로 화면의 display를 찾을 수 있을 때까지) 기다렸다가 계속하므로 에뮬레이터 홈 화면을 캡처하지 않습니다. 화면의 전역 옵션 「버벅이면 게임 재시작」을 끄면 0으로 설정한 것과 같습니다
- 서버 점검(「서버 점검 중」 화면): 방치 플레이는 10분마다 「타이틀로 돌아가기」를 눌러 다시 로그인해 확인하고, 서버가 열리면 방치 플레이를 이어 갑니다(「휴대폰 알림」을 켜 두면 기다리기 시작할 때와 서버가 열렸을 때 알립니다). 다른 작업은 바로 실패합니다
- 게임 업데이트: 로그인할 때 뜨는 「데이터 다운로드」(추가 게임 데이터)는 자동으로 「확인」을 눌러 다운로드합니다. 「새 버전 감지」(앱 스토어에서 설치 패키지를 업데이트해야 함)는 자동으로 누르지 않으며, 작업은 바로 실패하고 방치 플레이도 멈춥니다. 게임을 직접 업데이트한 뒤 다시 시작하세요
- PC 메모리 부족: PC에서 더 커밋할 수 있는 메모리(작업 관리자 「성능 › 메모리」의 「커밋됨」)가 1GB 아래로 남으면 로그에 한 번 알립니다. 연주 프로세스가 메모리를 할당하지 못해 종료되면 화면에 PC 메모리 부족이라고 표시합니다. 메모리를 많이 쓰는 프로그램을 닫거나 PC를 다시 시작한 뒤 다시 시작하세요. 작업 관리자 「세부 정보」 탭을 「커밋 크기」로 정렬하면 어떤 프로그램이 쓰고 있는지 볼 수 있습니다

## 작동 원리(요약)

1. **내비게이션**: 스크린샷 → OCR → 글자와 위치로 현재 화면 판단 → 버튼 탭. 버튼은 우선 글자로 정확하게 위치를 찾고, 찾지 못하면 고정 좌표를 씁니다
2. **곡 인식**: 밴드 확인 화면에서 곡명을 OCR로 읽고, 채보 사이트와 국제 서버의 다국어 곡명과 퍼지 매칭해 musicId를 얻습니다
3. **동기화**: 시작을 누른 뒤 화면이 멈추기를 기다렸다가, 첫 노트가 그 노트의 레인 위쪽에 나타나는 것을 감지하고 앞쪽 가장자리를 추적합니다. 노트가 판정선에 다가가는 움직임은 `y - y_h ∝ exp(t/τ)`를 따르므로, 피팅한 뒤 도달 시각을 외삽해 곡의 기준점(0점)을 구합니다
4. **연주**: 채보를 터치 제스처(탭, 플릭, 롱, 트레이스)로 변환하고, minitouch로 터치를 주입하며(대안은 MuMu IPC), 고정밀 타이머로 제때 보냅니다. 게임의 판정 테이블에 따라 인접한 노트끼리 터치를 서로 「가져가는」 것을 피합니다: 동시에 가로로 미는 이웃 노트는 시작점을 엇갈리게 하고, 뒤이은 탭에 터치를 빼앗길 수 있는 위쪽 플릭 / 트레이스는 미리 누릅니다
5. **결과**: 판정 수와 FAST/SLOW를 읽어 결과를 기록하고 오프셋을 보정합니다
